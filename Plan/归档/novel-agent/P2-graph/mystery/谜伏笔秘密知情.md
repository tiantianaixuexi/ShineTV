# 伏笔 · 秘密 · 知情 · 信息节奏

## 分工（勿混）

| 系统 | 管什么 |
|------|--------|
| Foreshadowing | 作者埋的设定钩子与回收 |
| Secret | 真相 + 谁在何时知道 |
| Mystery/InformationFlow | 面向读者的问→线索→揭示节拍 |

三者可互相引用实体 id。

## 伏笔 foreshadowings

| 列 | 说明 |
|----|------|
| title, content | |
| status | PLANNED → PLANTED → DEVELOPING → REVEALED → RESOLVED |
| setup_ch, payoff_ch | 埋/收 |
| importance | 0–100 |
| truth | 真正含义 |
| entity_ids_json | 关联人/物/事件 |

状态机：只允许相邻迁移；RESOLVED 后不得再 plant。

## 秘密 secrets

| 列 | 说明 |
|----|------|
| content | 表面表述 |
| truth | 真相 |
| reveal_ch, reveal_condition | 何时/条件揭露 |
| entity_id | 主体 |
| scope | world / character / faction |

例：老者其实是皇帝（读者不知）；林夜之父未死（林夜不知）。

## 知情矩阵

### secret_knowledge(secret_id, entity_id, knows, chapter_known)

| 角色 | knows |
|------|-------|
| 作者（系统） | 隐含 YES（库内有 truth） |
| 读者 | 由 reveal 节拍决定，不单独存读者行时用 mystery_beats |
| 各人物 | secret_knowledge |

### character_knowledge
泛化事实知情（见人物分册）。

**Writer 约束**：POV 或说话者 `knows=0` → 禁止直接说破 truth。

## 信息节奏 Information Flow

### mysteries
question, answer, status(open/developing/answered/abandoned), ask_ch, answer_ch, importance, entity_id

### mystery_beats
| beat_type | 含义 |
|-----------|------|
| question | 抛出问题 |
| hint | 线索（可多条） |
| reveal | 阶段揭示 |
| answer | 最终回答 |
| red_herring | 烟雾弹 |

| 列 | mystery_id, chapter_id, content, target_entity_id, ord |

`reveal` 时回写 `secret_knowledge.chapter_known`（若绑定 secret）。
