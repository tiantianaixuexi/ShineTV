# 坑与手法（踩过的坑 / 事故 / 验收手法）

> 这里放**经验**：踩过的坑、翻过的车、可复用的验收手法。规则（硬性的）在 `../Doc/`，进度在 `PROGRESS.md`。
> 逐日细节在 `.codebuddy/memory/YYYY-MM-DD.md`。

## 1. 施工纪律（血泪）

1. **一次只改一处，立刻 `cmake --build build -j 8` 验证**；不通过不进下一步。
2. **改完头文件立刻编译**：出现过 `replace_in_file` 报"成功"但结构体没写进 `.h`，只有编译才暴露。
3. **`replace_in_file` 失败会把这个文件清空**（两次实例：根 `AGENTS.md`、`Plan/HANDOFF.md` 变成 0 字节）→
   每次编辑后立刻确认文件长度/内容；被清空就用原文重写。
4. **机械替换（按名字批量改符号）必须排除"定义该符号"的文件** —— 曾把 `UiState.cpp` 里 `kActivities` 的**定义**
   也替换掉，并让访问器变成自递归。
5. **`#include` 绝不能放进 `namespace` 内部** —— 头里的 `namespace shine::app::…` 会变成相对声明，名字全部不可见。
6. 命名避免"变量遮住命名空间"：过渡别名曾叫 `ui`，遮住了 `app::ui` → 改名 `g_ui`。
7. 临时脚本 / 备份 / 假服务端 / 临时日志 sink **用完就删**；`build/` 不留 `_*` 文件。
8. 抓日志要给 `core/Log.cpp` 临时加 `basic_file_sink_mt("<**绝对**路径>", true)`（GUI 的 stdout 重定向抓不到），
   验完**必须回退并干净重编译**。

## 2. GUI 验收（不要让它变尸体）

- **别用 `Start-Process` 让 GUI 常驻**：从 AI shell 起的 GUI 事后 `Stop-Process` 常 `Access denied`，
  留下**尸体条目**（`Threads=0 Handles=0`）。它不占资源，但会短暂锁住 `build\ShineTVStudio.exe`，
  导致链接报 `ld.exe: cannot open output file … Permission denied`（**这不是编译错误**），等一两分钟或重启即好。
- **正解：`CloseMainWindow()`**（发 `WM_CLOSE`）—— 实测进程能正常退出、**不留尸体**（`Get-Process ShineTVStudio` 为空）。
  见 `../scripts/capture_window.ps1`（已内置"最多等 6s，超时才 `Stop-Process -Force`"）。
- **盲跑判据**（不看屏幕时判断程序是否正常）：`MainWindowTitle` 非空 + `MainWindowHandle != 0`
  + 主线程 `ThreadState=Wait` / `WaitReason=UserRequest` + CPU 时间随秒递增。
  **`Responding` 会瞬时为 False，别单凭它判卡死。**

## 3. AI 自己截图看界面（2026-09-16 打通）

不用再全靠用户肉眼回归。**截图存 PNG → `read_file` 直接读图**（多模态），小字用 `crop_zoom.ps1` 放大 3–4 倍再读。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\capture_window.ps1 -Out build\_shot.png
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\crop_zoom.ps1 -In build\_shot.png -Out build\_crop.png -X 1590 -Y 55 -W 390 -H 260 -Scale 4
```

三个坑（脚本注释里也写了）：

1. **DX11 交换链用 `PrintWindow` 只有标题栏、客户区全黑** → 必须置前 + `CopyFromScreen`；
2. `SetForegroundWindow` 对非前台进程会被系统拒绝（实测抓到的是别的窗口）→ 先 `SetWindowPos(HWND_TOPMOST)`
   再用 `AttachThreadInput(前台线程, 自己, true)` → `SetForegroundWindow` 才生效；
3. 窗口默认 2000×1125 在 (125,125) → 先挪到 (0,0) 并把宽高裁到屏幕内再抓。

**PowerShell 脚本必须纯 ASCII**：Windows PowerShell 5.1 读无 BOM 的 UTF-8 会把中文变乱码并报
`The string is missing the terminator`。

## 4. 编码坑（中文 Windows 必看）—— 已统一收口到 `util/Encoding.h` + `util/File.h`

本机 `GetACP() == 936`（GBK），而项目内部约定**文本一律 UTF-8**。三类坑（**都踩过、都已修**）：

| 坑 | 长什么样 | 正确做法 |
|----|----------|----------|
| **Win32 A 版 API 返回 ANSI(GBK) 字节**（`FormatMessageA`、CRT `strerror`、libhv `socket_strerror()`） | 塞进 UTF-8 的 `std::string` → **ImGui 把每个非法字节渲染成一个 `?`**（实测 UI 显示「网络错误: `?????????`」，实为 GBK「函数不正确。 」9 字节） | `util::AcpToUtf8()` 转一次；能改 W 版就改（`util::WinErrorMessage()` 已封装）。规则见 `../Doc/RULES-LANG.md` §13.5 例外 6b |
| **宽↔窄"逐字符截断"**：`std::string(w.begin(), w.end())` | 中文路径直接报废（`SettingsPath()` / `GraphHost::Narrow()` 各一处；实测坏串 20 字节、非法 UTF-8） | `util::Utf16ToUtf8` / `util::PathToUtf8` |
| **路径用窄字符串构造/打开**：`path{std::string}`、`path.string()`、`std::ifstream(std::string)`、`fopen` | 中文目录/文件名：路径变乱码、文件**打不开**（实测：中文目录里 2 张 PNG 探针全失败、窄串 ifstream 打不开同一文件） | 路径一律 `std::filesystem::path` 传递；字符串互转走 `util::PathFromUtf8 / PathToUtf8`；文件读写走 `util::OpenInput/OpenOutput/ReadFileBytes/WriteFileBytes` |

**已迁移的点位（2026-09-16）**：`core/Settings.cpp`（设置路径 + Load/Save）、`graph/GraphHost.cpp`
（`graph.json` 路径；**VNS 的 `LoadFromFile/SaveToFile` 用窄字符串，故改成我们用 `util` 读字节 →
`LoadFromJson` / `ToJson()` 写回**）、`media/ImageFetch`（接口收 `path`，原先收窄串）、`media/MediaLibrary`、
`media/ui/OutputView`（`path.string()` 上 UI/剪贴板）、`app/FileDialog`（去掉本地 ToWide/ToUtf8）、
`gallery/ImageScanner`（去掉本地路径转换）、`gallery/MetaProbe|ImageLoader|decoders/PngDecoder`（打开文件走 `util::OpenInput`）、
`comfy/ComfyHttp`（错误文案走 `util::WinErrorMessage`）。

**验收手法（可复用）**：把进程的 `%APPDATA%` 用 `SetEnvironmentVariableW` 临时指向一个**中文目录**，
再跑 `SaveSettings → 改内存值 → LoadSettings` 往返 + 中文路径文件 IO → **PASS 15 / FAIL 0**。

**仍存的小限制**：`app/Fonts.cpp` 用 ImGui `AddFontFromFileTTF(const char*)` 加载 `C:\Windows\Fonts\*.ttc`
（ImGui 内部走窄字符串 `fopen`）—— 系统字体目录恒为 ASCII，**当前无影响**；若以后支持"用户自定义字体目录"，
需改成 `util::ReadFileBytes` + `AddFontFromMemoryTTF`（注意 ImGui 用 `IM_FREE`= `free` 释放，缓冲要用 `malloc`）。

**这些 `.md` 是 LF-only**：PowerShell 5.1 的 `Get-Content` 数行数会错 → 脚本处理要用 .NET
`File.ReadAllLines/WriteAllText` 或 Python（`newline=""`）。

## 5. 离线验收手法（ComfyUI / 网络不在也能验）

WIN32 GUI 程序 `AllocConsole` + `freopen(CONOUT$)` → stdout 抓不到，所以拿"日志行"证据要这样做：

1. **假服务端**：Python 标准库手写（`socket` + 手工 WS 握手
   `base64(sha1(key + "258EAFA5-E914-47DA-95CA-C5AB0DC85B11"))` + 不掩码文本帧 + ping 回 pong
   + 顺带应答 `/system_stats` `/queue` `/object_info` `/history` `/prompt`）；把 `settings.json` 的
   `comfyBaseUrl` 临时指向它（**先备份**）。
2. **纯解析函数**：临时 `.cpp` 直接链接工程**已编译的 `.obj`**
   （`build/CMakeFiles/ShineTVStudio.dir/src/...obj`），加 `-DFMT_HEADER_ONLY -DSPDLOG_FMT_EXTERNAL` +
   include 路径 + `-static*`；程序里 `log::Init()` 后断言 → 一次拿到 PASS/FAIL 计数与耗时。
3. **整机无头链路**：链接**全部工程对象**（排除 `main.cpp.obj`）+ `build/lib/libhv.a`
   + Windows 库（`d3d11 dxgi d3dcompiler dwmapi user32 gdi32 shell32 ole32 uuid secur32 crypt32 winmm iphlpapi ws2_32`）；
   `ImGui::CreateContext()` → `graph::Init()` → `ClearGraph()` 之后就能像 App 一样建图/编译/提交，
   还能 `ComfySession::Init(url)` + `Tick()` + `async::DrainUiQueue()` 直接跟真机 ComfyUI 联调出图。
4. **注意事项**：`log` 未 `Init()` 时是**静默**的，要证据必须显式 `Init()`；
   异步回调（如 `LastPromptId()`）必须**泵几帧**再断言，否则假失败。

> 战绩：P3 收尾 **PASS 50 / FAIL 0**（含真机 `executed` 出图）；G-S4 **PASS 40 / FAIL 0**
> （1 万张扫描 448ms、内存 +7.48MB、零像素分配、中文路径、来源可用性）。

## 6. 施工坑速查

- **yyjson**：`yyjson_doc_get_root(doc)`（不是 `yyjson_get_root`）；数组追加 `yyjson_mut_arr_add_val(arr, val)`；
  可变 API 的键是 **C 字符串**（`yyjson_mut_obj_add_int(doc, obj, "k", v)`）。
- **VNS（third/VisualNodeSystem）**：`NodeArea::Render()` 渲染期把 ImGui style 放大 `Zoom*2`、字体 push 成 `16*Zoom`，
  控件宽度/位移都要乘 `Zoom`；**插口位置按 `Size.y` 均分** → 想让控件行与插口行对齐，必须**输入 ↔ 插口 1:1**；
  `Node::Draw()` 是空实现；注册 `NODE_FACTORY.RegisterNodeType(type, ctor, copyCtor)` **无注销**；
  连线从节点侧反查（`NodeSocket::GetConnectedSockets()`），reroute 在 `Connection` 内部（节点侧不可见）。
- **C++26 反射**（`-freflection` 已在 CMake）：必须 `std::define_static_array(...)` 物化 +
  只能用 `template for (constexpr auto m : …)` 展开（运行时 `for` 报 `consteval-only variable … not declared constexpr`）。
  现成实现：`src/util/Reflect.h`，直接用。
- **`std::function` vs move-only**：投递 `gallery::Image` 这种不可拷贝资源要用
  `std::move_only_function<void()>`（`core/Async.h` 已改）。
- **GPU / ImGui 纹理生命周期（2026-09-17 踩过崩溃，必看）**：
  `ImGui::Image()` 只是把 **SRV 指针**记进本帧 draw list，真正使用是**本帧末尾** `ImGui_ImplDX11_RenderDrawData()` 的
  `device->PSSetShaderResources(0, 1, &texture_srv)`。所以「**同一帧** Upload → 画 → `Release`」就是**用已释放的 SRV 去问驱动**：
  崩溃栈实测 `wWinMain (main.cpp:190) → ImGui_ImplDX11_RenderDrawData (imgui_impl_dx11.cpp:328) → d3d11.dll`，
  WER 报的出错模块是显卡驱动 `nvwgf2umx.dll`，异常码 `0xC0000005`；而且**崩的时间随机**（15–25 秒不等，因为释放后的内存
  有时还没被复用），极易误判（我先后误判成"ComfyUI 没连上就崩"和"WS 阻塞假死"）。
  **规则**：交给 ImGui 画过的纹理至少活到**本帧命令列表提交之后** —— 要么跨帧保活（`views/temp/TextureSelfCheck.cpp` 现在就是），
  要么在**下一帧开头 / `DrainUiQueue` 阶段**释放。**G-S8 的 `GpuTextureCache::EvictIfNeeded()` 必须遵守同一条**（不能淘汰本帧已画过的纹理）。
- **libhv 的默认 logger 是惰性 + 非线程安全**（`third/libhv/base/hlog.c:534`）：宏 `hlog` = `hv_default_logger()`，首次调用会
  `logger_create()` + **`atexit(hv_destroy_default_logger)`**。若**多个线程同时首次**写 libhv 日志（ComfyUI 连不上时正是这种：
  多个 worker 同时报 connect 失败），会在 msvcrt `_onexit` 的锁上**死锁**（gdb 栈：
  `http_client_connect → hv_default_logger → msvcrt!atexit → _onexit → RtlSleepConditionVariableCS`，**永不返回**）。
  → 已在 `app::Init()` **最前面**（建线程池之前）调用 `comfy::EnsureLibhvReady()` 单线程初始化；`ComfyHttp::Send()` 里另有 `call_once` 兜底。
- **进程退出不能被后台 I/O 拖住**（"关窗了进程不消失"的根因）：仍有 worker 卡在 libhv 里时，`static_thread_pool` 析构的 `join`
  会永久阻塞。现在策略：`async::Shutdown()` **故意泄漏线程池**（不 join、只停止接单 + 清空信箱），`main()` 末尾在**显式清理完
  D3D/纹理之后**用 `std::_Exit(0)` **跳过 CRT atexit 与静态析构**。实测 ComfyUI 关着跑 60s 后关窗 **0.2 秒退出、exit code 0**。
- **PowerShell**：`Set-Content` 不带显式编码会被工具拦截；`Get-Content` 数 LF 文件行数不准；
  `Remove-Item` 批量删多路径会触发 safe-delete 守卫（改成一次一个路径）。
- **ComfyUI**：核心更新了但依赖没跟上 → 报 `ModuleNotFoundError`/`ImportError` 就
  `pip install -U <报错的包>`（历史：`comfy-aimdo 0.4.13→0.5.5`、`av→18.1.0`）；
  无头启动**必须带 `-RedirectStandardOutput/-RedirectStandardError`**，否则异常随进程消失。
  **忙碌 ≠ 卡死**（`../Doc/RULES-COMFY.md` §12）。

## §8 VNS（第三方节点系统）三个"静默失败"点（2026-09-17，导入官方模板时逐个踩到）

> 共同点：**不报错、不崩、计数看着还对**，只是"东西少了/看不见"。只看返回值判断不了，得看现象。

1. **`NodeArea::CenterViewOnAllElements()` 会静默失败**：它内部 `SetRenderOffset()` 会把偏移**夹到 `GRID_SIZE`**，
   目标超范围时**直接 `return false`**（`SubSystems/VisualNodeArea/VisualNodeAreaRendering.cpp:763-767`）。
   后果：导入官方模板（坐标 `y≈4850`）后"节点数正确、画布一片空白"。
   → 修法在**我们这侧**：导入后先按 AABB 把整图**平移到原点附近**（相对布局不变），再 `CenterView()`（含 `GroupComment` 一起位移）。
2. **插口类型是"两边 `AllowedTypes` 求交集"**（`VisualNode.cpp:176-211`）：只要声明类型字符串不相等就拒绝。
   ComfyUI 的三种类型（**并集** `"FLOAT,INT,BOOLEAN"`、**通配** `*`/`ANY`/`COMFY_MATCHTYPE_*`、**动态父插口** `COMFY_AUTOGROW_V3`/`COMFY_DYNAMICCOMBO_V3`）一律接不上。
   → 修法：`BuildSockets()` 拆并集 + 给通配补 `"ANY"` 标记；**再 override `Node::IsValidAsNewConnection`**（**必须连它一起覆盖**）。
3. **`NodeSystem` 会用它复检并断开已有连线**：`VisualNodeSystem.cpp:1967-1973` 调 `IsValidAsNewConnection(...)` 判定"这条线还合法吗"，
   不合法就 `TryToDisconnect`。只覆盖 `CanConnect`/插口类型、不覆盖 `IsValidAsNewConnection` → **刚连上的线下一帧被它剪掉**。
   → 两者必须成套改（VNS 自带的 `FloatVariableNode` 等就是这个套路）。

## §9 验收手法：让自检**显式摆好状态**，别依赖"默认值 + 鼠标"

- 2026-09-17 截图验收模板窗时，左边分类高亮落在「LLM (17)」而不是默认的「全部 (646)」：**不是代码 bug**，
  而是 `capture_window.ps1` 会把主窗口置前/挪到 (0,0)，浮窗恰好落在**真实鼠标**指针下，鼠标的一次点击/wheel 被投递给了浮窗。
- 结论：验收脚本**要自己把要展示的状态设成确定值**（例：自检里显式 `g_tpl.category = <目标分类>` 并打一行日志），
  再截图；否则"默认值"可能被真实输入改掉，截图不可复现。日志里带一行"当前分类/条数"能自证。
- 同理：`imgui.ini` 会记住浮窗位置与停靠页 —— 见 §8 与 MEMORY §10"不要手改 ini"。

### 截图脚本（`scripts/capture_window.ps1`）2026-09-17 加固
- **抓错窗口**：原来用 `$proc.MainWindowHandle` 认主窗。有 ImGui 浮窗（多视口/浮窗被点过）时它可能指向**浮窗**，
  于是脚本把浮窗挪到 (0,0)、截出浮窗的图，`CloseMainWindow()` 也关错对象（主窗不退出 → 只能 `Stop-Process`）。
  甚至出现截到**桌面别的窗口**（浏览器）的情况。→ 改成 **按标题找窗**（`FindWindow($null, "ShineTV Studio")`，标题在 `main.cpp` 定死），
  找不到才回退 `MainWindowHandle`，并且**新增 `-WindowTitle` 参数**。
- **hover-only 的 UI 截不到**（tooltip、hover 高亮）：新增可选参数 `-CursorX/-CursorY/-CursorSettleMs`，
  在置前之后把真实光标停到目标控件上再截（默认 -1 = 不动）。
- ⚠️ **两个必须知道的副作用**：
  1. 它会**移动用户的真实鼠标**（脚本结束不还原）→ 跑之前先确认用户没在用鼠标；用完提醒一下。
  2. 它会把浮窗挪到 (0,0) 并把新位置**写进 `imgui.ini`**（ImGui 自己保存）→ 下次运行浮窗可能出现在左上角，属正常后果。
- **鼠标落点别按估算**：本轮"想 hover 左栏分类"连续两次落在**遗留的「纹理自检」浮窗**上（它盖住了那块区域）→ 先看整张截图确认控件位置，
  再定坐标；或者干脆换成"自检显式设置状态"（见上一条，更可靠）。

### P5.6 新增的三条（2026-09-17）

1. **整屏截图会"整块黑"**：本轮中途 `capture_window.ps1` 连续给出 `mean=0.0x`（连"桌面任意点采样"探针也是 **0**）——
   不是我们的窗口问题，而是当时**屏幕/会话根本不在渲染**（`PrimaryScreen` 尺寸还从 2560x1440 变成了 2048x1152）。
   判据：**先探一次任意点平均亮度**，为 0 就说明环境不可截，隔一会儿重试（本轮重试第 2、3 次就恢复了）；
   别改脚本、也别怀疑 ImGui 后端。**拿不到截图时先用"文本自检报告"顶上**（`SHINE_*_SELFTEST` 那种），事后再补图。
2. **环境变量名必须 ASCII**：`SHINE_BOTTOM_TAB=输出` **永远不生效** —— Windows 环境变量进来的是 **ANSI 代码页**字节（本机 936），
   跟源码里的 UTF-8 字面量比不出来。开关名统一 ASCII（`output` / `log` / `queue`），中文只出现在 UI 上。
   同理**路径类**开关（`SHINE_VIDEO_SELFTEST=<文件>`、`SHINE_VIDEO_DEMO_OUTPUT=<文件>`）要先 `util::AcpToUtf8(raw)` 再 `PathFromUtf8`
   （本轮已顺手修掉 P5.5/P5.6 钩子里的这个隐患）。
3. **ImGui 表格"列数/列序变了"必须换表 id**：P5.6 给分镜表加列后，旧 `[Table]` 设置按**列索引**套宽度 → 表头"产物"被顶到最左列
   （数据其实都还在各自列上，纯视觉错乱）。改列序同理。做法：`BeginTabItem`/`BeginTable` 的 id 加后缀（`##shot_table_p56`），
   让 ImGui 丢弃旧设置重建；代价是用户自定义过的列宽会重置一次。
   - 附带：**验收开关"只在前 N 帧生效"**。`ImGuiTabItemFlags_SetSelected` / `SetNextWindowFocus` 若**每帧都设**，
     用户就永远切不走那一页/那个 tab（等于劫持 UI）。用 `frames++ < 60` 之类限流，之后自动交回。
