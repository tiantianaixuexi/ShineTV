## 2026-11-23 imgui 19303 升级 + 全局动画接线（ImAnim）

- 决定：`third/imgui` 核心 14 文件升 1.93.0 WIP(19297) → 1.93.1 WIP(19303)（源 `F:\c++\imgui`，原版覆盖）；ImAnim 经 SHA256 六文件比对与 `F:\c++\imgui_third\ImAnim` 逐字节同版，无需复制。
- 发现（API 破损）：19303 删了 1.90.9 的 Tab 旧别名（`ImGuiCol_TabActive/TabUnfocused/TabUnfocusedActive`）⇒ `Theme.cpp` 编译失败；改 `TabSelected/TabDimmed/TabDimmedSelected` + 补两个新 Overline 槽。backends 仍 19297（F: 只有核心文件），实测可编，下次拿全上游再同步。
- 发现（引擎层，最重要）：`kit/Anim` 的 Transition* 封装恒传 `init_value==target`（pinned 重建语义），而 ImAnim 默认开 lazy-init，「通道不存在且 target≈init」时**不建通道直接返回 target**（`im_anim.cpp:944`）⇒ 补间永不启动、动画静默退化成硬切换——**编译过、像素终值全对，只有运行时看得出来**。修法：`ReserveTweenPool` 里 `iam_set_lazy_init(false)`。教训：接线动画后要实测「运行时真的在动」，编译过 ≠ 动画在跑。（此坑由 anim-widgets-b 子代理读引擎源码发现。）
- 决定：动画接线纪律 = **终值恒等**（settle 值与原硬切换逐值相同；pinned 取证期间 Transition* 直接落 target ⇒ 像素判据不受影响）、通道约定（0=hover 主底/1=按压位移/2=描边辉光/3=文字/4+=指示器滑动）、tid=0 纯展示控件不接补间（防 id 撞车）。范围：Button/Card/Choice/Input/Table/Tree/List/Menu/Tooltip/浮层壳层全覆盖（清单见 refactor/animations.md）；结构性跳过（Segmented 胶囊、Tree 展开高度、投影档渐变、浮层整体缩放）各有注释理由。
- 验证：构建全绿（shine_imgui + exe）；四门禁 PASS。1:1 回归最终 **90/90 overall=PASS**（hover 12/12、overlay 13/13、book/asset 快照收敛、真图判据全绿）——动画 settle 恒等得证。⚠️ 中途出现过「-O3 确定性崩溃于 RefreshTexts + 图片链全红」两族假象，后来各自证伪：① 崩溃是**增量构建的陈旧对象污染**（imgui 19297/19303 混链），`Build.bat --release --clean` 清洁重建后消失——曾误判为「WIP 的 UB（优化敏感指纹）」，**是错的**，别再按 UB 路线查；教训：升级 vendor 后第一轮必须清洁构建，增量构建的崩溃先怀疑混链。② 「图片链全红 + hover 10/12 + overlay broken=3」只在 **gdb 下**出现（计时失真），同一二进制正常跑全绿——教训：取证结论只认正常 harness 跑法，gdb 下的判据红是调试假象。
