# 2026-09-30

## 2026-09-30 双端架构定型：webui 只做效果、imgui 1:1 复刻（P0–P7，日期不详归最接近）

- 决定：`webui/`（React+CSS）是视觉唯一基准、只做效果不管功能；`src/ui/imgui/` 是真界面按它 1:1 复刻；`shine_core` 零 Qt 零 ImGui 一行不改。旧 Qt 前端整体删除，构建零 Qt 依赖（P0–P7 共 51 步全清）。
- 理由：同样的现象在错层上改会改成另一种错——改视觉前先归因到页面层/主题层/字体层/宿主层。
- 教训：`webui/` 不入库，`refactor/design-spec.md` §2 内联的 31×5 色值表才是可复现记录；核对 CSS 前先确认 webui/ 还在本机。见 AGENTS.md「双端架构」。

## 2026-09-30 截图取证不可跨轮逐字节比对（实测）

- 发现：同一二进制连跑两轮，80 张里 48 张字节不同（时钟/动画相位/日志时间戳）；「改完再 diff 上一轮」会被噪声淹没。
- 决定：等值性改用同轮重样判据（`identical-*-pairs`）+「两轮间稳定的 32 张」子集比对（实测 32/32 未变即足够）。
- 教训：像素差不是内容指标（离屏跨进程约 2000px、跨构建约 40000px 噪声）；本仓两次「投影差 180px/0px」的真相都是界面里印着的工程路径。详见 refactor/记忆.md『取证与判据纪律』。

## 2026-09-30 novel.db fixture 是判据的成立条件（反复踩过）

- 发现：`SeedReportFixture()` 不建 `novel.db`，缺库时侧栏树/资产树退化成诚实空态，`hover-tree-node`/`hover-asset-card` 永远命中不到——同一份代码缺库 9/11+FAIL、有库 11/11+PASS，「图照常 saved、判据照常红」。这套输入曾随一次仓库瘦身被删掉。
- 决定：fixture 由 `out/_make_fixture.ps1` + seed 播种，缺库直接失败；硬门禁卡枚举覆盖度（8 种资产状态、`source_kind` ≥2 种等）——枚举没铺满 = 对应分支永远没人验。
- 教训：改动一律追加 seed（新行 100+ id 号段），改完必须重跑 `_make_fixture`（`_run_review` 只拷不重建，忘了重建时判据以 NO-IMAGE 的样子红）。详见 refactor/记忆.md『取证基建』。

## 2026-09-30 默认跑旧产物的假绿（2026-09-30 修）

- 发现：取证脚本默认 `-Exe` 曾指向 `build-p7` 里两小时前的旧二进制（体积小 26 MB）照样报 PASS；`scripts/run_reviews.ps1` 也把 `-Exe` 写死过 `build\`。判据只认产物、不认产物的出处。
- 决定：改成按 `build/release → debug → build` 解析并打印时间戳；纪律是核对日志里 `exe:` 那行。
- 教训：「默认跑错产物」是判据通过最难发现的假绿；构建失败时脚本仍会跑起来，那两轮数字全是旧二进制的——判据只认「构建成功且取证 PASS」。详见 AGENTS.md「两个最容易骗自己的假信号」。

## 2026-09-30 门禁自身的三处盲区（第四轮，已修）

- 发现：`find-rect-wh-misuse` 传 `-SelfTest` 被静默忽略照报 0（与真通过字面相同）；按名字枚举尺寸变量漏掉 `w/h/colW/thumbH` 等 6 种误用；`check-colors` 两条规则互斥导致 `ImU32(0x…)` 双向漏网。
- 决定：判据按形态写（结尾字符 `^\w*[wh]$`）不按名字枚举；补 `-SelfTest`（9 真+6 假，第十二轮再扩 11 真）；加规则必须同时加真样本。
- 代价：`check-colors` 豁免 7→24 acknowledged 是判定面变宽不是退化，别拿更早的 7 当基线。
- 教训：扫描器报 0 不等于没有；改门禁单独一轮做，改完先跑自检证明仍能抓。详见 refactor/记忆.md『门禁自身的盲区』。

## 2026-09-30 嵌套 child 抢走 HoveredWindow，浮层按钮点不动（第八轮）

- 发现：工作区 `ScrollRegion` 的 `NoMouseInputs` 不向嵌套 child 传播（总览右栏/分镜时间线/底栏列表照样抢 `HoveredWindow`）⇒ 查看器的 × 在分镜页 `hovered=false`、换到资产页就好——哪一处坏取决于绘制顺序与鼠标位置。
- 决定：闸门提成 `kit::OverlayMouseGate()`（外壳每帧写、`ScrollRegion` 缺省读），调用点不再各传一次。
- 教训：「每个 child 都要按它退出命中测试」靠人记一定会漏；同族还有「先注册者独占 HoveredId」「遮罩只画不注册（ScrimPaint）」「浮层用 ForegroundDrawList」。详见 refactor/记忆.md『命中与叠放』。

## 2026-09-30 注入鼠标键的释放沿会永久丢失（第八轮）

- 发现：探针写 `SetFrameMouseButtonOverride(false)` → `Clear` → 泵帧，而宿主只在覆盖还开着的那帧才推释放事件（Host.cpp:352）⇒ `io.MouseDown[0]` 永久为真；受害的是**之后第一条**按下探针（`IsMouseClicked` 要求上一帧抬起），写错的那条自己不红。
- 决定：释放沿必须在覆盖还开着时泵一帧再清；探针逐条打 `down/clicked/hover/open` 诊断。
- 教训：一个信号至少三种原因（注入没到位/环境塌了/目标真没变），探针里记「系统实际看到什么」并在没到位时先短路。详见 refactor/记忆.md『取证基建』。

## 2026-09-30 kit::Image 两档 key 号段撞车，viewer-full 判据假红（第九轮）

- 发现：`ImageKey`/`ImageKeyFull` 写成 `FNV(path) | bit` 而不是先清后置，约 1/4 路径两档撞 key ⇒ 大图档 `try_emplace` 登记不进去 ⇒ `viewer-full` 报「大图没请求过」假红（大图明明在屏上，连跑 5 轮 5/5）。
- 决定：号段公式改 `(FNV(path) & ~(bit62|bit61)) | 自己那一位`，加 256 条就地探针自检 `image-keys` 进 overall。
- 教训：判据红了先查判据前提；撞不撞取决于路径 FNV（含取证输出目录）⇒「换个目录名结果就翻」是前提坏了的指纹，不是随机。详见 refactor/记忆.md『判据成立前提被写坏』。

## 2026-09-30 真设定图是异步链，等待只能放 Shoot 唯一入口

- 发现：真图走 worker 解码 → `PostToUi` → 上传 GPU，只泵一两帧抓到的必然是占位画——「链断了」与「拍得太早」在截图上完全一样；按调用点补等待漏一处就是一处随机失败（`assets-leaf-selected` 实测两轮一有一无）。
- 决定：等待收进 `Shoot` 单一入口；`sheet-images=settled`（`requested>0 && pending==0` 两半）进 overall。
- 教训：pending 要按现用档位算（`PendingImageFullCount`），拿总数会因注册表只增不减永远等不到 0，判据以「链断了」的样子假红。详见 AGENTS.md「以为『异步的图』拍得到」。

## 2026-09-30 duplicate-hits 815 是首次可观测值，不是回归（第二轮）

- 发现：此前每轮 `duplicate-hits` 都是 0，但那几轮 book/asset-snapshot 全 TIMEOUT（一直在测空气）；815 = 2 个 `.tree` 折叠箭头 × 约 408 帧 + 一处真布局缺陷（`DrawJumpButtons` 溢出压住树首行 8px）。

## 2026-09-30 数指定色像素是唯一可靠的像素取证（第三轮前后）

- 决定：截图跨轮不可复现，取证改数指定色值像素（`out/_colorcount.ps1`）；真设定图是两张刻意选在主题调色板外的纯色 PNG（`#FF2D55`/`#7CFF00`），上没上屏一数便知。
- 发现：像素缓冲是 RGBA8（R 在偏移 0，权威是 Capture.cpp 的注释），形参名曾叫 `bgraPixels`——按 BGRA 数恒得 0，而 0 恰好也是「图没上屏」的读数，一次就伪装成产品缺陷。
- 教训：色判据必须带上界（色退化成一块面时只判下界会判绿）；「两处同卡」要一次抓图数两色。详见 AGENTS.md『地雷』。

## 2026-09-30 line.*/fill.* 的 alpha 口径错了，不是算法错了（第三轮）

- 发现：15 个半透明 token 被按 `--bg-surface` 摊平成实色存进 JSON；原记录「只能二选一」的定性带着人走弯路。
- 决定：JSON 原样存 CSS rgba，绘制时按实际已画内容做 source-over 混合（ImGui 本来就是 alpha 混合，一行不用加）；实测 `#202734` 4902→38、`#29313E` 7→3987。
- 教训：底色是画的时候才知道的量，不该在数据层提前定死；改动前逐主题交叉验算旧值 = `FlattenOver(raw, bg-surface)`。详见 refactor/design-spec.md §2.0.3。

## 2026-09-30 滚动一族：不提交 item 就是滚不动（第四轮横向滚动）

- 发现：自绘控件只加 draw call 不提交任何 item ⇒ 三个 `ScrollRegion` 全部从来不能滚；只开 `horizontalScroll` 更糟（`ContentSize.x` 恒 0，内容被裁且到不了，比原来「至少不画半截」更坏）。
- 决定：`setContentHeight()`/`setContentWidth()` 两个都声明才滚得动；`SetScrollHereY` 在 child 构造期拿到的是上一帧残留，改 `SetScrollY(自报内容高 − 可视高)`。
- 教训：列表按容器高度 `break` 是静默截断（50 个任务只画前 6 个、无提示）；`ScrollRegion` 判据要同时打期望上限与 `GetScrollMaxY()`。详见 refactor/记忆.md『滚动、裁剪、视口』。

## 2026-09-30 假数据/死代码一族合并教训（历轮清零）

## 2026-09-30 中文发糊是结构性的（日期不详，归最接近）

- 发现：三条根因缺一仍糊——`RasterizerDensity` 缺省 1.0（1.92 起唯一光栅化分辨率旋钮）、`PixelSnapH` 压掉 `OversampleH`、半点字号（10.5/11.5/…）按整数档光栅化再缩放必重采样。
- 决定：`kRasterizerDensity = 2.0` 四处全设，A/B 边缘梯度 22.55→39.26（+74%）；刻意不设 `GlyphRanges`（legacy 路径，换回旧后端要重新接，否则全是 '?'）、别开 `Alpha8`（vendored OpenGL3 后端硬编码 RGBA，图集烘不出来）。
- 教训：图集统计读 `GetSizeInBytes()` 不要硬编码 `Width*Height*4`。详见 refactor/记忆.md『字体与图集』。
