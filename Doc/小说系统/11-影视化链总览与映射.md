# 11 · 影视化链总览与映射

> 影视化链消费正文链的产出，**不回写正文**。本卷定义它的位置、与正文链的解耦边界、以及最关键的「叙事状态 → 视觉状态」映射规则。同时如实记录当前实现的最大断点：**两套分镜模型之间没有桥**。

## 0. 本卷范围与不做什么

**范围**

- 影视化链的位置、解耦原则与边界。
- 阶段 V1–V10 的总览（终点 = 分镜提示词；`V11 GENERATION` 为可选下游），细则见 `12` / `13`。
- **叙事状态 → 视觉状态的映射规则**（本卷核心）。
- 视觉 Canon 的语义与回写边界。
- 叙事分镜 → 生成分镜的转换契约。
- **视觉资产的生产流水线与状态机**（§2.6，本卷与 `12` 并列的核心）。
- **依赖等待与降级策略**（§2.7）。

**不做**

- 不定义分镜/镜头/节拍字段的完整结构 → `12`（结构）与 `02` §2.7/§2.8/§2.9（契约）。
- 不定义四类专项 Prompt 的写法 → `13`。
- 不定义出图调用与校验 → `13` §2.6。
- 不定义正文侧状态 → `01`。

## 2. 目标设计

### 2.1 位置与解耦原则

| # | 原则 |
|---|---|
| P1 | **只读正文**：影视化链读取**已提交**的 `scenes` / `chapters` / 叙事分镜；**永不修改正文与叙事状态** |
| P2 | **可独立重跑**：同一章可反复跑，不影响第 N+1 章的生成 |
| P3 | **Canon 分离**：视觉 Canon（`visual_canon_logs`）与叙事 Canon（`canon_logs`）**各管各的**，互不提升 |
| P4 | **失败隔离**：某镜生成失败不阻断其余镜（`09` §2.2 `CONTINUE`） |
| P5 | **输入唯一**：`scenes` 是唯一衔接点（`03` §2.8） |

### 2.2 链路阶段（细则见 `12` / `13`）

```
正文链（已提交）
   ↓ Scene / 叙事状态
V0 ASSET_PIPELINE（角色/场景资产：正脸 → 四视图 → 基础身体 → 服装）  ← 前置，见 §2.6
   ↓
V1 SCENE_BREAKDOWN   → V2 DIRECTOR_INTENT → V3 PERFORMANCE → V4 SPATIAL
   ↓
V5 CAMERA → V6 TIMELINE → V7 AUDIO
   ↓
V8 CONTINUITY（纯机器校验）
   ↓
V9 STORYBOARD（NarrativeShot[] → shots 表）
   ↓
V10 PROMPT_GEN（PromptArtifact[] → prompt_layers）   ← 影视化链终点
   ↓
V11 GENERATION（可选下游：→ Comfy；无评审）
```

**实现进度（S23）**：**V9 `STORYBOARD` 已落地** —— `src/agent/NovelStoryboard.*`：读该章的 `scenes`（V9 的输入是**已提交的场景**）→ **一次 LLM 推演 V1–V8**（SCENE_BREAKDOWN…AUDIO 合并，与 `03` §2.2 允许 T2–T9 合并同理）→ 解析 `NarrativeShot[]`（`02` §2.7）→ 落 `shots` 表。

- 落列的字段：`scene_id`/`ord`/`duration_note`/`start_state_json`/`end_state_json`/`timeline_json`（`{duration_s,beats}`，K24 的读法）/`character_ids_json`（从 `start_state.characters` 抽出，**K22 的受检对象**）/`prompt_text`/`negative_text`/`dialogue`。
- **无专列的契约字段**（`transition`/`performance`/`spatial`/`camera`/`audio`）**只存盘**：完整契约落在 `work/ch<NNN>/storyboard.json`（V10 产生成 Prompt 时从那读）—— 不硬塞进语义不符的列，并在 `warnings` 里显式说明（不静默丢）。
- **不做 V8 的判定**：`CONTINUITY` 是纯机器校验（K09），本模块只保证 `start_state`/`end_state` 落对，判定归 `NovelChecks`。
- CLI：`--novel-storyboard <chapter_id>`。
- **仍未做**：V11 出图接线（含 K19–K21 回填）、V1–V8 的逐步展开。

**V10 `PROMPT_GEN` 已落地（S24）**：`src/novel/NovelPromptGen.*`。**先查后写** —— 组装**早就存在**（`NovelVisual::Assemble` 九层 `base→…→quality`，`prompt_layers` 是它的输入），V10 缺的只是**账**：现在把 `Assemble` 的结果写成 `PromptArtifact`（`chain=visual` / `stage=V10` / `target_kind=shot`，带 `input_state_hash` + `references_json` = 该镜出场角色资产的 `sheet_rel_path`）。**不调 LLM**（纯规则组装，可复现）。
- PV1/PV2 与不变式 I9：同 `input_state_hash` → **复用**（不重写）；哈希变了 → 重新生成。
- ⚠️ **表的列缺口（如实记）**：`prompt_artifacts` **没有** `version` / `generation_ref` 两列（PV3–PV5 的载体）→ 版本号暂记在 `model_hint`（`v=N layers=M`）；等真需要版本历史/结果回溯时再加列。
- ⚠️ **`04` §2.5 的输入清单只列了叙事侧**：S24 为 `chain=visual` **补充**了 `visual_assets` / `visual_states`（否则改了角色外观哈希不变、产物被误判"可复用" —— V10 自检撞出来的）。
- ✅ **多角色已支持（S25）**：`AssemblePromptInput` 加 `character_ids`，`Assemble` 对**每个**出场角色各拼 `base`/`stage` 层（原先只拼 `character_id` 一个 ⇒ 一镜两人时**第 2 个人在 prompt 里完全隐形**）。第 1 个视为主角色；"谁在前景/谁在背景"的表达留给 `camera` / `spatial` 层。
- ⚠️ **`Assemble` 里原先还有个"用第一个角色预解析 `assetId`"的老逻辑**，会把多角色分支挡掉（S25 自检撞出来）—— 已删，角色的资产解析统一放在"角色外观"段逐个做。
- CLI：`--novel-prompt <chapter_id>`。

### 2.3 **叙事状态 → 视觉状态的映射规则**（本卷核心）

这是把「文本世界」变成「影像世界」的唯一规则集。**当前实现完全缺失这一层**。

#### 映射总表

| 叙事侧（`01`） | 视觉侧 | 映射规则 |
|---|---|---|
| `entities(kind='person')` | `visual_assets(kind='character', entity_id)` | **一对一**；缺 asset 时在 `V1` 生成 `PROPOSED` 提案（`P3`：不自动 CANON） |
| `entity_personas.appearance` | `visual_assets.base_desc` | 首次映射：人设外观 → 基准描述；后续以 `visual_assets` 为准 |
| `character_status.body_state`（按章） | `visual_states.appearance` + `effects` | **按 `chapter_id` 解析**（`ResolveVisualState`）：伤势/体力 → `effects`；衣着 → `clothing_asset_id` |
| `character_status.emotion_json` | `ShotRow.expression` / `mood` | 情绪维度 → 表情基线（映射表见下） |
| `entity_ownerships`（第 N 章持有） | `visual_states.item_asset_ids_json` | 角色此刻持有的物品 → 该阶段可见道具 |
| `entities(kind='clothing'/'prop')` | `visual_assets(kind='item'/'clothing')` | 一对一 |
| `entities(kind='location')` + `location_details` | `visual_assets(kind='location')` + `scene_visuals` | 地点基准外观；**按章变化**（如焚毁）走 `scene_visuals` |
| `scenes`（单场） | `scene_visuals` + `scene_layouts` | 场次视觉与站位布局 |
| `scenes.time_label` | 光照/天候 | `time_label` → `lighting_defs` 的选择依据 |
| `world_rule`（如「此地无月」） | `visual_styles` 的硬约束 | 世界规则可翻译为视觉硬约束，禁止违反 |
| `secrets`（POV 不知情） | **不得出现在画面** | 同不变式 I2 的视觉版（见下 §2.3.3） |

#### 2.3.1 情绪 → 表情基线（示例映射，取值需可配）

| `emotion_json` 维度 | 阈值 | `expression` 基线 |
|---|---|---|
| `fear >= 70` | — | 瞳孔收缩、呼吸浅、嘴角收紧 |
| `anger >= 70` | — | 下颌绷紧、眉压低 |
| `trust <= 20` | — | 目光回避、身体侧向 |
| `sadness >= 70` | — | 眼睑下垂、肩线内收 |
| 全维度 < 40 | — | 中性基线 |

**规则**：映射是**基线**，`NarrativeShot.expression` 可在基线内微调，**不得反向覆盖**（不得让某一镜的表情改变 `character_status.emotion_json`）。

#### 2.3.2 视觉状态的时间解析（复用 `01` §2.3.2）

```
第 N 章的视觉状态 = visual_states WHERE asset_id=:a
                    AND from_chapter <= :N AND (to_chapter = 0 OR to_chapter >= :N)
                    ORDER BY from_chapter DESC, ord DESC LIMIT 1
（无命中 → 回退 ord 最小的阶段；沿用 NovelVisual.cpp:139-153 的语义）
```

**新增要求**：`V8 CONTINUITY` 必须校验「`visual_states` 的 `from_chapter` 改动能被 `character_status` 的对应变化解释」——否则记 `visual_state_mismatch`（对应 `06` §2.3 K22 的扩展）。

#### 2.3.3 视觉侧的知情边界（不变式 I2 的视觉版）

| 规则 | 内容 |
|---|---|
| VK1 | 若某实体的存在本身就是「POV 不知情的秘密」，则该实体的视觉资产在 `chapter_id < reveal_ch` 的镜中**不得出现** |
| VK2 | `visual_assets` 的 `canon_status='DRAFT'` 资产**不得进入生成**（必须先定稿） |
| VK3 | `layer` 为 `mask`/`private` 的动态字段（`08` §2.6）默认不参与视觉描述 |

### 2.4 视觉 Canon 与回写边界

| # | 规则 |
|---|---|
| C1 | 视觉 Canon 写 `visual_canon_logs`；**不写** `canon_logs`（P3） |
| C2 | `V1` 生成的 asset 提案写 `PROPOSED`；升 `CANON` 需人工确认或满足「同一 asset 在 ≥3 镜中一致使用」的自动条件 |
| C3 | 出图结果（`generated_images`）的状态机沿用现有：`QUEUED/RUNNING/PROPOSED/CANON/NON_CANON/FAILED/DISCARDED`（`NovelImageStore.cpp:247-252`） |
| C4 | 视觉 Canon 的变更**不**触发正文链的 `input_state_hash` 失效（各管各的） |
| C5 | 但叙事状态的变更**必须**触发视觉链的 `PromptArtifact` 失效（`04` §2.5 H4）——单向依赖 |

### 2.5 叙事分镜 → 生成分镜的转换契约（**当前缺桥**）

```
NarrativeShot（02 §2.7，叙事：怎么拍）
      ↓  转换器（ToGenShot）  ← 本集要求新增
GenShot（02 §2.8，生成：怎么交给 Comfy）
```

**转换规则**：

| `GenShot` 字段 | 来源 |
|---|---|
| `title` | `NarrativeShot.shot_id` + 场景标题 |
| `prompt` | `PromptArtifact.prompt`（由 `13` 的 Image/Video Prompt Agent 产出）；**不得**直接用 `NarrativeShot.prompt_text` |
| `mode` | 有 `firstFramePath` → `first_last_frame`；否则 `reference` |
| `firstFramePath` | 该镜的叙事分镜图（若已生成）；否则空 → 走纯文生图降级 |
| `referenceImages` | 由 `PromptArtifact.references` 映射到 `visual_assets.sheet_rel_path`，**上限 9** |
| `characterAssetPaths` | `NarrativeShot.start_state.characters` 对应的 `visual_assets` |
| `chainFromPrevious` | 同场景内非首镜 → `true`；**但该镜自带 `firstFramePath` 时取 `false`**（否则 H3 按"链式优先"忽略首帧图 —— 自己跟自己打架；S6 细化） |
| `width`/`height` | 由 `VideoProject.sceneWidth/Height` 决定；为 0 时取分镜默认再对齐（纠正规则的唯一来源是 `VideoProject::Sanitize()`） |
| `seed` | 由 `NarrativeShot` 的稳定键派生（保证同一镜可复现）；**禁止纯随机** —— 实现 `StableShotSeed` = FNV-1a(`sceneTitle\|shotId\|ord`) → `[0,2^63)`，产出**永不**留 `-1` |
| 采样参数 | 取 `VideoProject.scene*` 系列（`steps`/`cfg`/`denoise`；`length` 默认 `kDefaultLength`=107） |

**要求**：转换器必须是**纯函数**（同输入同输出），且产出的 `GenShot` 必须先经 `06` §2.3 的 K20/K21 校验再提交。

**实现（S6）**：`src/video/NovelShotBridge.*` —— `ToGenShot(sceneTemplate, scene, options) → ToGenShotResult{ok, error, project, issues, degradations}`。输入是**只读 DTO**（`NarrativeShotInput`/`NarrativeSceneInput`）：读表与「`PromptArtifact.references` → `visual_assets.sheet_rel_path`」的路径解析由小说侧做完再传进来，`src/video` **不依赖** `novelcore`（`11` §3 的 11-1）。K20/K21 **不重复实现对齐规则**：映射出原始值 → 跑一次 `VideoProject::Sanitize()` → 比对"纠正前 → 纠正后"得到 `issues{checkId, severity}`（宽高/帧数纠正 = `K20/low`；参考图超限 = `K21/high`）并同步进降级账；`strictRefLimit=true` 时 K21 直接拒绝产出。**没有 PromptArtifact 的镜 → 整场失败**（不产半成品）。

### 2.6 视觉资产生产流水线（状态机 + 派生链）

> **本节的由来**：旧文档与 `01` §2.6 只描述了「有什么」，没有描述「怎么生产出来」。
> 而角色的形象不是一张图，而是**一条有先后依赖的产出链**：
> 新建人物 → 建形象 → 生成提示词 → **正脸** → 依正脸生成**四视图（基础身体／内衣层）** → **服装层**。
> 缺了这一节，下游拿到一个「还在生成中」的形象就**不知道该等还是该跳**。

#### 2.6.1 生产状态机

`visual_assets` 必须能表达「生产到哪一步」。新增语义列 `status`（**与 `canon_status` 正交**）：

| `status` | 含义 | 可被下游消费 |
|---|---|---|
| `PENDING` | 已登记，未开始 | ❌ |
| `PROMPTING` | 正在生成提示词 | ❌ |
| `REF_READY` | **正脸就绪**（身份锚点） | ✅（仅用于派生四视图） |
| `SHEET_READY` | **四视图就绪**（基础身体／内衣层已锁定） | ✅（用于分镜的 `referenceImages`） |
| `WARDROBE_READY` | **服装层就绪** | ✅ |
| `READY` | 全链完成 | ✅ |
| `FAILED` | 生产失败 | ❌（需重试或人工） |
| `STALE` | **上游变了，本步需重做** | ❌ |

**迁移方向**（单向，回退即 `STALE`）：

```
PENDING → PROMPTING → REF_READY → SHEET_READY → WARDROBE_READY → READY
                └────────────── 任一步失败 → FAILED ──────────────┘
   （叙事状态或上游产物变化 → 下游全部 STALE）
```

**关键规则**：

| # | 规则 |
|---|---|
| S1 | `status`（生产态）与 `canon_status`（作者认不认）**正交**；**下游只以 `status` 判断是否可用，不等 `canon_status`**——否则无人值守会永远等不到（`07` §2.5 C1 的同一条精神） |
| S2 | `VK2`（§2.3.3）的「`DRAFT` 不得进入生成」改为：`canon_status='DRAFT'` **可以**进入**派生**（正脸→四视图），但**不得**作为最终分镜的 `referenceImages` |
| S3 | 任一步产出变化 → 其**所有下游** `STALE`（与 `04` §2.5 H3 的下游失效同构） |
| S4 | `status='READY'` 的资产在叙事状态未变时**不得重生成**（`input_state_hash` 一致即复用） |

#### 2.6.2 派生链与层级

#### 2.6.4 与 `generated_images` 的关系

| 表 | 职责 |
|---|---|

#### 2.6.5 孤儿态回收（**已实现**）

进程崩溃/重启会让 `RUNNING` 行永远停在「生成中」——这正是「下游不知道怎么办」的直接成因。

| 项 | 内容 |
|---|---|
| 实现 | `novelcore::ReapStaleImageJobs(db, staleSeconds)`（`src/novel/NovelImageStore.h/.cpp`）；`staleSeconds <= 0` = 无条件回收（启动用） |
| 行为 | `RUNNING`/`QUEUED` 且 `updated < now - staleSeconds` → 改判 `FAILED`，`error='stale: …'`，写 `audit_logs(actor='startup_reaper')`，并 `log::Warn` 报告条数 |
| 调用点 | `NovelView.cpp::EnsureProjectSchema()`（工程打开的入口），传 `0` |
| 自检 | `RunImageQueueSelfCheck` 断言：`stale`（`updated=0`）必须改判、`fresh`（`updated` 在未来）必须保留 |
| **遗留** | 目前挂在 **UI 项目打开路径**；将来若有 headless / MCP 直连入口，**必须一并调用** |

### 2.7 依赖等待与降级策略

下游需要一张资产但它还没 `READY` 时，只有三种选择，**必须选一种并写死**：

| 策略 | 行为 | 代价 |
|---|---|---|
| **A 阻塞等待** | 等到 `READY` 或超时 | 无人值守下会卡死 |
| **B 跳过并降级** | 无参考图 → 纯文生图，`degraded=true` 记账 | 角色一致性下降 |
| **C 挂起该镜，先跑无依赖的镜**（**本集选定**） | 该镜回队列；超期后降级为 B | 需要队列与优先级 |

**选定组合：C 为主 + B 兜底。**

| # | 规则 |
|---|---|
| W1 | 缺参考图**不等于失败**：允许降级，但 `visual_artifacts.degraded=1` 且进 `ContextReport` |
| W2 | **降级必须可见**（与 `04` §2.4「降级必须可见」同一条纪律）：写入章级 `cost_report.json` 与 `stop_report.md` 的降级清单。**生成侧已实现**（S4/S5）：`src/video/GenerationLedger.h` 的类型化 `kind`（`no_reference` / `no_controlnet` / `size_aligned` / `ref_truncated` / `param_unified` / `chain_ignored` / `first_frame_ignored` / `name_collision`）+ `VideoTaskState.degradations`，并追加落盘 `<VideoOutputDir()>/degradations.jsonl`（一行一条）——章级报告（S9）从这里合并 |
| W3 | 挂起超期阈值：单章内该镜挂起超过 `09` §2.4 的单章墙钟预算即降级 |
| W4 | **一镜多产物**：`Shot.jobs`（`ShotJobRecord[]`，逐次记账 `{jobId, kind, status, files, error, at}`），状态列**按 job 聚合**，后完成的**不得覆盖**先完成的 —— **已实现**（S5；早期 `lastPromptId` 单值写法已废弃） |
| W5 | **队列与优先级**：`VideoTaskRunner` 升为小队列（忙时**入队**，空闲按优先级取；同级 FIFO；中断顺带清队列）；`VideoJobPriority{Asset=0, SceneImage=10, ShotVideo=20}` → **角色资产（V0）优先于分镜图**，因为后者依赖前者 —— **已实现**（S5；`Asset` 档的真实生产者待 `13` U1 统一出图入口） |
| W6 | 生成**一致性校验**：同一角色的两次生成结果需做一致性比对（当前 `AppendChecklist` 只查文件存在/尺寸，`NovelImageStore.cpp:36-77`）——不一致记 `visual_consistency` issue |
