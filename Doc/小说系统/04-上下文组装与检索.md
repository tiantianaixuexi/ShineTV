# 04 · 上下文组装与检索

> 本卷把旧文档「最小 Context 原则」这句口号变成可执行算法：分层选材、相关性打分与排序、去重、长度预算分配、超限分级降级，以及「输入状态哈希」的复用与失效语义。这是「不要提示词爆炸」的技术实现处。

## 0. 本卷范围与不做什么

**范围**

- 定义上下文的分层结构与每层的选材来源。
- 定义检索：相关性打分、排序、去重规则。
- 定义预算分配与**超限分级降级**（必留 / 可丢），替代当前的尾部硬截断。
- 定义 `input_state_hash` 的计算与复用/失效判据。
- 定义长程记忆的存储与检索策略。
- 给出工具化的按需检索目录（替代一次性灌入）。

**不做**

- 不定义契约字段 → `02`。
- 不定义时间语义查询 → `01` §2.3.2。
- 不写 Prompt 文本 → `05`。
- 不定义检索失败后的评审规则 → `06`。

## 2. 目标设计

### 2.1 三条原则

| # | 原则 | 含义 |
|---|---|---|
| A1 | **相关 > 最近** | 「前 3 章摘要」是时间邻近，不是语义相关。相关性由打分决定，不由 `ord` 决定 |
| A2 | **按需拉取 > 预先灌入** | 能通过工具在运行期拉的，不进初始上下文 |
| A3 | **预算内分级降级** | 超预算时按「必留 / 可丢 / 可摘要」三档降级，**不做尾部截断** |

### 2.2 分层选材（重定义 L0–L4）

| 层 | 名称 | 内容 | 档位 | 预算占比 |
|---|---|---|---|---|
| L0 | 任务头 | 当前链/阶段/章、`ChapterGoal`、`input_state_hash` | **必留** | 5% |
| L1 | 硬约束 | 书名、文风（`writing_style`）、`author_rules(severity='error')` | **必留** | 10% |
| L2 | 近场前情 | 前一章结束时状态 + 前一章摘要 + **本章直接续接的场景** | **必留** | 20% |
| L3 | 相关切片 | 打分选出的角色/地点/物品/关系/知情/伏笔 | 可丢 | 45% |
| L4 | 长程背景 | 世界规则、主题、剧情线进度、谜团、**相关**历史章摘要 | 可摘要 | 20% |

**与现有实现的对应**：L1 已正确；**L2 从「最近 3 章」改为「前一章 + 直接续接」**；L3 从「整表 top-N」改为「打分选取」；L4 从「整表 top-N」改为「相关召回 + 摘要压缩」。

### 2.3 相关性打分（L3 的核心）

对候选对象 `c`（角色/地点/物品/关系/伏笔/历史章），分值 `S(c)`：

```
S(c) = w1·在场 + w2·提及 + w3·未结 + w4·时间近 + w5·重要度 + w6·POV 相关 − w7·已解决
```

| 权重 | 项 | 取值 |
|---|---|---|
| `w1` | **在场** | `c ∈ ScenePlan 的 cast / location / items` → +50 |
| `w2` | **提及** | `c.name` 出现在本章 `ChapterGoal`/`OUTLINE`/`user_hint` 中 → +30 |
| `w3` | **未结** | 伏笔未回收 / 谜团未答 / 剧情线未结 → +20 |
| `w4` | **时间近** | `chapter_id` 距当前章 ≤ 3 → +15；≤ 10 → +8；否则 0 |
| `w5` | **重要度** | 伏笔/冲突按 `importance` 折算（0–100 → 0–20） |
| `w6` | **POV 相关** | 与 `pov_entity_id` 存在关系边 → +15 |
| `w7` | **已解决** | 已 `RESOLVED` 的伏笔 / `answered` 的谜团 / 已关闭的关系 → −30 |

**排序**：按 `S(c)` 降序；同分按 `time_label` 新者优先。

**去重（必须实现）**：

| 场景 | 规则 |
|---|---|
| 同一实体出现在多层 | **只保留最高层**的那份完整表述，其余层写引用（`见实体 12`） |
| 关系双向 | 同一对实体只保留一条，合并 `reason` |
| 伏笔与秘密指同一事实 | 保留伏笔（作者账本），秘密只保留 `POV 可见` 的部分 |
| 角色既在 cast 又在揭示名单 | 合并为一条，取并集的字段 |

**禁止**：把 `GetCharacterSlice` 的 6 个子块原样全贴。只贴打分后**进入预算**的部分；其余通过工具在生成中按需拉取（A2）。

### 2.4 预算分配与分级降级

**预算单位**：以 UTF-8 字节计（沿用 `kDefaultMaxBytes` 语义），默认 **12000**；按 `09` §2.4 的模型上下文窗口调整。

**分配顺序（硬性）**：

```
1. L0 必留（不裁剪）
2. L1 必留（author_rules 若超限则只保留 severity=error 的前 N 条，N 见下）
3. L2 必留（前一章摘要可压缩到 200 字）
4. L3 按 S(c) 降序填充，直到占比上限
5. L4 用剩余预算，先放世界规则，再放剧情线/谜团；不足则整层省略
6. 若仍有剩余预算 → 不放任何东西（宁可空，不要灌）
```

**降级三档**：

| 档 | 含义 | 何时触发 |
|---|---|---|
| **必留** | 绝不裁剪 | L0/L1/L2 |
| **可丢** | 按 `S(c)` 从低到高丢弃 | L3 超出 45% 占比 |
| **可摘要** | 用「一句话摘要 + 实体 id」替代全文，摘要仍不够则整条丢 | L4 |

**必须记录降级日志**：每次组装产出 `ContextReport{kept:[id], dropped:[{id, reason}], summarized:[id], bytes_used, degraded:bool}`，写入阶段产物旁的 `04_context_pack.json`。**降级必须可见**，否则无人值守下会静默丢关键状态。

**禁止**：尾部 `TruncateUtf8` 硬截断（现有行为）。必须由 §2.4 的算法决定丢什么。

### 2.5 `input_state_hash`：复用与失效

**定义**：`input_state_hash = sha1(规范化后的状态摘要)`

**纳入哈希的内容**（顺序固定、只取影响生成的部分）：

```
contract_version
chain           # text | visual
stage           # 阶段名
chapter_id
pov_entity_id
sorted(相关的 entity ids + 各自的 updated 时间戳)
sorted(相关 foreshadow ids + status)
sorted(相关 plotline/mystery ids + status)
sorted(field_defs 中 scope/entity_kind 命中本阶段的 field_key + updated)
writing_style.updated
author_rules 的 id 集合（severity=error）
# —— S25 补充（下述两条都是"真实运行逼出来的"）——
prompt_rule_version                            # 组装规则版本
chain=visual 时另含：
  sorted(visual_assets.id + base_desc + sheet_rel_path + status)
  sorted(visual_states.id + appearance + environment_hint + canon_status)
```

**S25 补充说明**：
- **视觉输入**：原清单只列了叙事侧。但视觉产物（`PromptArtifact`）的失效判定**必须**包含视觉输入 —— 否则改了角色的 `base_desc` / 阶段外观，哈希不变、旧 prompt 被误判"可复用"，**不变式 I9 形同虚设**。故 `chain=visual` 时另含 `visual_assets` / `visual_states`。
- **`prompt_rule_version`**：**组装规则本身**变了（如 S25 把"只拼第一个出场角色"改成"拼全部出场角色"），输入状态没变、但产物**必须失效** —— 否则会出现"修了 bug，可真实工程里的旧产物永远不更新"（S25 实测踩到：改完多角色后重跑，旧产物被全部"复用"）。**改拼装规则就把这个版本号 +1**（当前 = `2`）。

**不纳入**：`memories`（会随生成增长）、`audit_logs`、`canon_logs`、无关实体的 `updated`。

**复用规则**（支撑 `03` §2.7 的 P1/P2）：

| 规则 | 内容 |
|---|---|
| H1 | 阶段产物落盘时记录其 `input_state_hash` |
| H2 | 重跑前先算当前哈希；与产物哈希一致 → **允许跳过该阶段**（幂等复用） |
| H3 | 不一致 → 该阶段与**全部下游**失效，从该阶段重跑 |
| H4 | `PromptArtifact` 的 `input_state_hash` 不一致 → 该 Prompt **不得复用**，必须重新生成（不变式 I9） |
| H5 | 任何写库操作（`entities` / `character_status` / `foreshadowings` / `relations` / `entity_fields`）都会改变相关实体的 `updated` → 自动触发下游失效 |

**这是「Prompt 是世界状态的派生结果」的工程实现**：状态变，哈希变，Prompt 失效，重新生成。

### 2.6 长程记忆

现有 `memories` 是扁平表 + 子串匹配，无法支撑「几百章可检索」。目标设计：

| 项 | 决定 |
|---|---|
| 存储 | **保留 `memories` 作为事件流**（`kind` / `chapter_id` / `content` / `summary`），作为唯一权威 |
| 检索 | **两级**：① 结构化过滤（`chapter_id` 范围 / `entity_id` / `kind`）；② 在过滤结果内做相关性打分（复用 §2.3 的 `S(c)`） |
| `embedding_blob` | **本期不用**，但保留列；若后续引入向量检索，必须先定义「嵌入模型 + 版本 + 何时重算」，否则不得写入 |
| 摘要树 | 每 10 章产出一次「十章摘要」（`kind='decade_summary'`），供 L4 低成本召回 |
| 反例 | **禁止**把全书 `memories` 全量读入上下文 |

### 2.7 工具化的按需检索（替代预先灌入）

Agent 在生成过程中可调用的检索能力（白名单由 `05` §2.6 按阶段给定）：

| 需求 | 工具 |
|---|---|
| 某人此刻状态 | `novel_get_character_slice(entity_id, chapter_id)` |
| 某人知道什么 | `novel_get_secrets_for(entity_id, chapter_id)` |
| 物品在谁手上 | `novel_get_ownership(entity_id)` |
| 事件的因果链 | `novel_get_event_chain(event_id, depth)` |
| 世界背景 | `novel_get_world_slice()` |
| 关系 | `novel_get_relations(entity_id)` |
| 查找实体 | `novel_list_entities(kind, filter, limit)` |
| 动态字段 | `novel_list_entity_fields(entity_id, chapter_id, layer)` |
| 前情摘要 | `novel_get_recent_chapters(k)` |

**约束**：工具返回必须受本卷 §2.4 的预算约束（单次返回上限见 `09` §2.4）；工具调用总数受 `kMaxToolCalls=20` 限制。

#### 2.7.1 声明式按需拉取（替代预判）

§2.3 的打分是**预判**——总控猜 Agent 需要什么。更可靠的做法是让 Agent **自己声明**：

1. `PLAN` 阶段产出 `ChapterPlan.context_requests`（`02` §2.2），形如 `{kind, entity_id, ref_id, chapter_id, depth, reason}`；
2. 总控按声明**逐条调用对应工具**（映射见下），而不是按固定 top-N 拉整表；
3. 结果按 §2.4 的预算裁剪后**追加**到 `ContextPack`，并把拉取记录写入 `ContextReport.requested` / `fulfilled` / `unfulfilled`。

| `kind` | 对应工具（`02` §2.2） |
|---|---|
| `character_slice` | `novel_get_character_slice(entity_id, chapter_id)` |
| `secrets_for` | `novel_get_secrets_for(entity_id, chapter_id)` |
| `ownership` | `novel_get_ownership(entity_id)` |
| `event_chain` | `novel_get_event_chain(ref_id, depth)` |
| `relations` | `novel_get_relations(entity_id)` |
| `entity_fields` | `novel_list_entity_fields(entity_id, chapter_id, layer)` |
| `recent_chapters` | `novel_get_recent_chapters(k)` |
| `world_slice` | `novel_get_world_slice()` |

**规则**：① 声明条目上限 `kMaxContextRequests = 12`，超限即 `code=contract` 失败；② 单条 `depth ≤ 3`；③ 未命中的声明必须在 `ContextReport` 里标 `unfulfilled` 并附原因——**不允许静默丢弃**。

### 2.8 反例清单（什么不该进上下文）

| 禁止 | 原因 |
|---|---|
| 整表 `ListOpenForeshadows()` 全量 | 几十章后数百条，其中绝大多数与本章无关 |
| `GetWorldSlice` 的 4 类全量（`world_rule`50 / `location`80 / `faction`50 / `power_system`20） | 200 条实体摘要 ≈ 上下文预算的数倍 |
| 未知情秘密的**内容** | 违反不变式 I2（现实现只报数量，**这一点是正确的，必须保持**） |
| 已 `RESOLVED` 的伏笔全文 | 已收束，只需保留标题 |
| 全书章节摘要 | 用摘要树 + 相关召回代替 |
| 任何 Prompt 文本 | Prompt 是按阶段加载的（`03` §2.4），不进上下文 |

### 2.9 视觉资产状态对上下文的影响

> 视觉链有自己的生产态（`AssetStatus`，`11` §2.6.1）。它**不得**污染叙事侧的上下文，但**必须**让 Agent 知道「哪些形象可用、哪些待重做」。

| # | 规则 |
|---|---|
| A1 | `status ∈ {SHEET_READY, WARDROBE_READY, READY}` 的资产：其外观描述与 `sheet_rel_path` **可进 L3** |
| A2 | `status='STALE'` 的资产：外观描述**不进 L3**（避免用过期外观写正文），但**保留标题与状态**——让 Agent 知道「这个角色的形象待重做」 |
| A3 | `status ∈ {PENDING, PROMPTING, FAILED}` 的资产：**只报状态与数量，不报内容**（与「未知情秘密只报数量」同一条纪律，`04` §2.8） |
| A4 | **资产生产状态不得成为正文生成的阻塞条件**：正文链只读叙事状态（`11` §2.1 P1）；`AssetStatus` 只影响 `V0`–`V10` |
| A5 | 因等待超时而降级的记录，必须进 `ContextReport`（对应 `06` K28「降级必须可见」） |
| A6 | `layer` 为 `mask`/`private` 的资产（多面身份的隐藏面）默认不进上下文（与 §2.6 的 `layer` 策略一致） |

**理由**：资产是**派生品**，不是世界状态（`00` §2.5）。把它当状态读会让上下文被"生成进度"污染；完全不读又会让 Agent 写出与影像不符的细节。**只读「可用性」，不读「进度」。**

## 3. 差距（逐条：现状 → 缺口 → 影响）

| # | 现状 | 缺口 | 影响 | 严重度 |
|---|---|---|---|---|
| 04-1 | 超预算时**从尾部截断** | 最先丢的是最相关的 L3/L4 | 关键状态被截掉（G4） | **S** |
| 04-2 | L3/L4 用「整表 top-N」 | 无相关性打分、无排序 | 大量无关内容挤占预算 | **S** |
| 04-3 | L2 取最近 3 章 | 时间邻近 ≠ 语义相关 | 跳跃式续写时前情错位 | **A** |
| 04-4 | 无去重 | 同一实体可能多层重复出现 | 预算浪费 + 信息互相矛盾 | **A** |
| 04-5 | 无 `input_state_hash` | 无法判断「能否跳过」「Prompt 是否失效」 | 断点续跑与 Prompt 复用均不可实现（G6/G9） | **S** |
| 04-6 | 无降级日志 | 静默丢数据 | 无人值守下不可诊断 | **S** |
