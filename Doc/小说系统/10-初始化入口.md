# 10 · 初始化入口

> 旧文档第 1 步就是「WORLD STATE」，但从没说这个世界状态从哪来。本卷补上这缺失的一环：一部新书从「什么都没有」到「可以开写第 1 章」的完整前置条件与门禁。

## 0. 本卷范围与不做什么

**范围**

- 新书启动的四种路径：导入既有设定、结构化录入、AI 生成 + 人工确认、模板。
- 初始化必须齐备的清单（缺一不可开写）。
- 「可开写第 1 章」的门禁校验。
- 分卷/分幕规划的最小要求。
- 初始化产物如何进 Canon（与 `07` 对齐）。

**不做**

- 不定义实体字段 → `01`。
- 不定义契约 → `02`。
- 不定义阶段机 → `03`（初始化是 T1 之前的阶段）。
- 不定义字段门禁细则 → `08`。

### 1.3 现状缺口

- **无初始化流程**：没有「填世界设定」的入口。
- `writing_style` 若为空，`ContextBuilder` 取文风时会取不到（`ContextBuilder.cpp:85-91`），**不影响运行但文风约束缺失**。
- `author_rules` 为空 → L1 无硬规则。
- 无「能否开写」的门禁检查：可以在空世界里直接点「生成本章」。
- `novelRootDir` **无设置 UI 入口**（`src/app` 搜 `novelRootDir` 零命中）。

## 2. 目标设计

### 2.1 四种初始化路径

| 路径 | 适用 | 输入 | 产物 |
|---|---|---|---|
| **A. 导入既有设定** | 已有设定文档/大纲 | Markdown / 纯文本 / JSON 设定集 | `entities` + 各 `*_details` + `field_defs` 提案 |
| **B. 结构化录入** | 作者想手工把控 | UI 表单（世界/人物/地点/势力/能力/物品） | 同上 |
| **C. AI 生成 + 人工确认** | 快速起步 | 一句话概念 / 主题 / 类型 / 篇幅 | AI 产出提案 → 人工确认 → 落库 |
| **D. 模板** | 复刻同类结构 | 既有工程导出 | 结构骨架 + 空内容 |

**四者共用同一套落库路径**（§2.4），只是「谁来填」不同。

### 2.2 初始化阶段（T1 之前）

本卷在 `03` §2.2 的正文链之前新增一个初始化链：

| # | 阶段 | 产物 |
|---|---|---|
| I1 | `INIT_CONCEPT` | 概念（书名、类型、主题、目标章数、目标字数） |
| I2 | `INIT_WORLD` | `world_meta` 键值 + `world_rule` / 地理 / 历史 / 社会 / 文化 / 技术 / 经济 / 历法 实体 |
| I3 | `INIT_POWER` | `power_system` + `ability`（含 `limit`/`side_effect`，见 `01` §2.1 R2） |
| I4 | `INIT_CHARACTERS` | `person` 实体 + `entity_personas` + `character_arcs` + `dialogue_styles` |
| I5 | `INIT_RELATIONS` | `relations` 初始边（含 `strength`） |
| I6 | `INIT_LOCATIONS` | `location` 实体 + `location_details`（含 `parent_id` 树）+ `location_distances` |
| I7 | `INIT_FACTIONS` | `faction` + `faction_details` + `faction_members` |
| I8 | `INIT_ITEMS` | `item`/`prop`/`treasure` + `item_details` + 初始 `entity_ownerships` |
| I9 | `INIT_SECRETS` | `secrets` + `mysteries` + 初始 `secret_knowledge`（谁知道初始秘密） |
| I10 | `INIT_MYSTERIES` | `mysteries` + `mystery_beats` 的初始节拍 |
| I11 | `INIT_PLOTS` | `plots`（主线/支线/感情线/悬疑线）+ `plot_beats` 的分幕骨架 |
| I12 | `INIT_STYLE` | `writing_style`（单行）+ `author_rules` + `dialogue_styles` |
| I13 | `INIT_FORESHADOW_SEED` | 计划中的伏笔（`status='PLANNED'`，含 `setup_ch`/`payoff_ch`） |
| I14 | `INIT_VOLUMES` | `volumes` + 每卷的 `ord`/`title`/`summary` |
| I15 | `INIT_GATE` | 门禁校验（§2.3） |
| I16 | `INIT_COMMIT` | 一次性提交全部初始化产物（事务，`07` §2.3 的同款机制） |

**可断点续跑**：I1–I16 与正文链一样按 `03` §2.7 落盘，允许「先填世界，明天再填人物」。

### 2.3 「可开写第 1 章」的门禁（`INIT_GATE`）

**全部满足才允许进入 `CHAPTER_INIT`**：

| # | 条件 | 判定 |
|---|---|---|
| N1 | `world_meta` 含 `book_title` | 存在性 |
| N2 | `writing_style` 有且仅有一行（`id=1`），且 `pov_mode` 与 `pacing` 非空 | 存在性 + 非空 |
| N3 | `author_rules` 至少 **1** 条 `severity='error'` | 计数 ≥ 1 |
| N4 | `entities(kind='person')` ≥ **1**（主角） | 计数 |
| N5 | 主角有 `entity_personas` 且 `goal`/`desire`/`fear` 非空 | 字段非空 |
| N6 | `entities(kind='location')` ≥ **1**（初始地点） | 计数 |
| N7 | `plots` 至少 **1** 条 `kind='main'`，且 `target_ch` > 0 | 存在性 |
| N8 | `mysteries` 至少 **1** 条（否则第 1 章无信息节奏） | 计数 |
| N9 | `secrets` 至少 **1** 条 `scope='world'` | 计数 |
| N10 | 每卷 `volumes.ord` 唯一且连续（从 1 起） | 唯一性 + 连续性 |
| N11 | `foreshadowings(status='PLANNED')` 的 `setup_ch` 与 `payoff_ch` 满足 `setup_ch < payoff_ch` 且 `setup_ch >= 1` | 区间 |
| N12 | `field_defs` 中 `is_system=1` 的 11 条种子齐备 | 计数 ≥ 11 |
| N13 | `agent_defs` 中 15 个内置 Agent 齐备且 `enabled=1` | 计数 ≥ 15 |
| N14 | 无「悬空引用」（任何 `location_id`/`entity_id` 指向不存在实体） | 引用完整性（对应 `06` §2.3 K02/K03） |

**门禁失败的输出**：`InitReport{passed:bool, failures:[{n_id, detail, fix_hint}]}`；**不允许**「警告后放行」。

### 2.4 初始化产物的落库与 Canon

| 规则 | 内容 |
|---|---|
| R1 | 初始化产物**一律经 `INIT_COMMIT` 事务写入**，不允许逐条散写 |
| R2 | 路径 B（结构化录入）由作者直接输入 → 直接写 `CANON` |
| R3 | 路径 C（AI 生成）→ 写 `PROPOSED`，UI 逐项确认后转 `CANON` |
| R4 | 路径 A（导入）→ 解析产物写 `PROPOSED`，**必须**走一次人工通读确认（导入的设定最易有隐蔽矛盾） |
| R5 | 路径 D（模板）→ 骨架写 `CANON`（结构无害），内容留空写 `PROPOSED` |
| R6 | 初始化阶段的字段提案走 `08` §2.3 的门禁（`PROPOSED` → 检查点自动升格或人工确认） |
| R7 | 初始化完成时写一条 `canon_logs`（`target_kind='project'`, `target_id=0`, `status='CANON'`）作为「已初始化」标志 |

### 2.5 AI 生成设定（路径 C）的约束

| # | 约束 |
|---|---|
| G1 | 生成前必须先确定「篇幅」与「类型」，否则 AI 会给出与目标不符的世界（如 15 章的故事配 300 章的世界观） |
| G2 | 一次最多生成 **1** 个域（人物 / 地点 / 势力 …），**禁止**一次性生成整套设定后让作者通读 |
| G3 | 每个域生成后**立即**由作者确认或改写，再进下一个域 |
| G4 | 生成的角色必须有 `goal`/`desire`/`fear`（`N5`）；生成的地点必须有 `loc_type`；生成的势力必须有 `goal`/`values` |
| G5 | AI 不得生成 `secrets` 的 `truth` 之外的任何 `secret_knowledge` 记录（即「谁都不知道」是默认）；知情必须由作者指定 |
| G6 | 生成时必须同时产出 `author_rules` 提案（AI 自己建议「这本书的文风硬规则」），由作者裁定 |
| G7 | 生成产物全部进 `PROPOSED`（`R3`），**禁止**自动 `CANON` |

### 2.6 分卷与分幕规划的最小要求

| 项 | 要求 |
|---|---|
| 卷数 | ≥ 1；每卷有 `ord`/`title`/`summary` |
| 每卷章数 | 建议 20–60；不在门禁内，但超范围时给告警 |
| 主线节拍 | `plots(kind='main')` 至少覆盖 `setup → rising → turning_point → climax → resolution` 五个 `beat_type`（允许后者在初始化时只写 `target_ch`） |
| 伏笔预算 | 每 10 章至少埋 **2** 条、回收 **1** 条（初始化时按此估算总量，写入 `INIT_FORESHADOW_SEED`） |
| 角色弧光 | 主角必须有一条 `character_arcs` 记录，`stage` 至少含「起点」与「终点」两阶段 |

### 2.7 初始化阶段的视觉资产

> 初始化只保证**叙事侧**齐备；**视觉资产不是开写的前置条件**（`11` §2.1 P1）。

| # | 规则 |
|---|---|
| I1 | `INIT_GATE`（§2.3 的 N1–N14）**不要求**任何资产 `READY` —— 加进门禁会让"想先写两章看看"变得不可能 |
| I2 | 但 `INIT_COMMIT` 之后**必须**为「前 N 章会出场的角色」建 `visual_assets` 记录（`status='PENDING'`、`canon_status='DRAFT'`）。`N` 默认 = `09` §2.5 的检查点周期（**10 章**） |
| I3 | **`V0` 批量生产不阻塞第 1 章写作**；推荐先写完前 **3** 章、人物稳定后再批量生产——否则人设未定就固化了形象，改起来代价大 |
| I4 | 路径 C（AI 生成设定）产出的角色，其 `visual_assets` 一律 `canon_status='DRAFT'`，需人工确认或满足"同一 asset 在 ≥3 镜中一致使用"的自动条件（`11` §2.4 C2） |
| I5 | 初始化的**场景**资产同理：`INIT_LOCATIONS`（§2.2 的 I6）只建 `entities`，`visual_assets(kind='location')` 由 `V0` 按需生产 |
| I6 | 资产生产状态**不写入** `INIT_COMMIT` 的 Canon 决议（`R7` 的 `canon_logs` 只覆盖叙事侧） |

## 3. 差距（逐条：现状 → 缺口 → 影响）

| # | 现状 | 缺口 | 影响 | 严重度 |
|---|---|---|---|---|
| 10-1 | `CreateProject` 只建空库 | 无任何世界内容 | 第 1 章之前无路可走（G14） | **A** |
| 10-2 | 无初始化流程与阶段 | 旧文档 §01 第一步就是「世界状态」，来源未定义 | 概念空洞 | **A** |
| 10-3 | 无「可开写」门禁 | 空世界也能点「生成本章」 | 生成无意义内容 | **A** |
| 10-4 | `writing_style` 无录入入口，可能为空 | 文风约束缺失 | 文风漂移 | **A** |
| 10-5 | `author_rules` 无录入入口，可能为空 | L1 无硬规则 | 连续性无硬约束 | **A** |
| 10-6 | `novelRootDir` 无设置 UI | 换库位置需改 settings.json | 易用性 | **B** |
| 10-7 | 无导入既有设定的能力 | 已有设定无法复用 | 只能用 AI 生成 | **A** |
| 10-8 | 无模板导出/导入 | 复刻同类结构需重来 | 效率 | **B** |
| 10-9 | 初始化产物无 Canon 语义 | 分不清「作者定的」与「AI 猜的」 | 后续校验无法区分 | **A** |
| 10-10 | 无初始化断点续跑 | 初始化中断需重来 | 体验 | **B** |

## 4. 验收判据

- [ ] §2.1 的四种路径都能落到同一套 `INIT_COMMIT`（`R1`）。
- [ ] §2.2 的 I1–I16 每个阶段都有产物，且能对到 `01` 的具体表。
- [ ] §2.3 的 N1–N14 **每条都可代码判定**，且失败输出 `InitReport` 明确「不允许警告后放行」。
- [ ] §2.4 的 R1–R7 七条规则齐备，且 R3/R4 明确「AI/导入产物必须进 `PROPOSED`」。
- [ ] §2.5 的 G1–G7 七条约束齐备；G2 明确「一次最多一个域」。
- [ ] §2.6 给出分卷、节拍、伏笔预算、角色弧光的最小要求。
- [ ] 门禁 N14 与 `06` §2.3 的 K02/K03 使用同一套引用完整性检查（不重复实现）。
- [ ] §3 的 10 条差距在 `00` §3 有编号对应。
