# 02 · 数据契约

> 本卷是全集**唯一的契约定义处**：阶段之间传递的每一个 JSON 结构，其字段、类型、枚举、必填、示例与版本都在此定义。字段的语义与存储归属见 `01`；判据与阈值见 `06`。其余各卷引用本卷，不得重复定义契约。

## 0. 本卷范围与不做什么

**范围**

- 定义全部阶段间契约：章节计划、事件、场景、状态差异、评审结论、叙事分镜、生成分镜、节拍、提示产物、生成结果、动态字段、错误与阶段信封。
- 定义每个字段的**类型 / 必填 / 枚举 / 示例 / 校验归属（机器 or 语义）**。
- 补齐旧文档中为空壳的契约（尤其 StateDiff 与分镜的起止状态/表演/空间/镜头）。

**不做**

- 不定义存储（表名、索引、时间语义）→ `01`。
- 不定义阶段顺序与重试 → `03`。
- 不写 Prompt 文本 → `05` / `13`。
- 不裁定阈值（如「多少章算超期」）→ `06`。

### 1.2 相关实现事实

- `LoadFromJson` 语义（`VideoProject.cpp:112-135`）：解析失败或根不是对象 → `false` 且**保持原工程不变**；仅缺字段 → `true` 取默认，随后 `Sanitize()`。
- `Sanitize()`（`VideoProject.cpp:33-107`）：宽高非正→默认再对齐 32；帧数非正→默认再对齐 `n%17==5`；参考图超 9 截断；`sceneWidth/Height>0` 时对齐 64；`sceneSteps<=0`→20。
- 结构化输出：`docs/compose/spec/novel-agent.md:92` 要求请求 `text.format` json_schema，**实际未实现**（当前靠 prompt 口头要求 + 事后 `yyjson_read`）。

## 2. 目标设计

### 2.0 契约书写规则

| 规则 | 要求 |
|---|---|
| C1 版本 | 每个顶层契约带 `contract_version`（整数，从 1 起）；破坏性变更必须 +1 |
| C2 命名 | 一律 `snake_case`；**不得**混用大小写或中文键 |
| C3 必填 | 表中标注「必填」的字段缺失即 **契约失败**，不是取默认 |
| C4 枚举 | 标注枚举的字段，取值必须在枚举内；未在枚举内即失败 |
| C5 未定义字段 | **禁止**。出现未在契约中定义的键即失败（防止 AI 自由加键污染下游） |
| C6 引用 vs 内联 | 已存在实体一律用 `entity_id` 引用；**不得**在契约中内联实体全量字段 |
| C7 时间 | 一切「第几章」用 `chapter_id`（= `chapters.id`）；**不得**用 `ord` 做跨表关联 |
| C8 校验归属 | 每字段标注 `机器` / `语义`；`机器` 字段必须由代码校验，`语义` 字段交给 LLM（见 `06` §2.1） |
| C9 来源 | 每个契约标注「由谁产出、被谁消费」 |
| C10 示例 | 每个契约至少给一个合法示例；**示例必须完整覆盖该契约的全部必填字段**（示例即测试用例） |

### 2.1 基础类型

| 类型 | 定义 | 说明 |
|---|---|---|
| `Id` | `int64` | 数据库主键；`0` 表示「尚未落库」 |
| `TempId` | `string`（`^[a-z_]+:[0-9]+$`） | 尚未落库的临时标识，如 `ev:3`、`sc:1`。**唯一性范围 = 同一章**（由契约的 `chapter_id` 界定命名空间），**不是**同一契约——因此 `EVENT_PLAN`(T4) 产出的 `ev:1` 可被 `SCENE_PLAN`(T6) 直接引用。**跨章不得复用同一 `TempId`** |
| `EntityRef` | `{entity_id:Id, kind:string, name:string}` | 只读引用快照；`kind` 见 `01` §1.1.2 |
| `ChapterRef` | `{chapter_id:Id, ord:int, title:string}` | |
| `TimeLabel` | `string` | 自由文本，须与 `01` §2.3.1 的世界历对齐 |
| `Severity` | `high` \| `mid` \| `low` | |
| `EventRole` | `actor` \| `victim` \| `witness` \| `beneficiary` \| `faction_actor` | 事件参与方式；**与 `SceneRole` 是两套不重叠的枚举** |
| `SceneRole` | `pov` \| `cast` \| `present` \| `offscreen` | 场景在场方式；**不含 `witness`**（那属于 `EventRole`） |
| `AssetStatus` | `PENDING` \| `PROMPTING` \| `REF_READY` \| `SHEET_READY` \| `WARDROBE_READY` \| `READY` \| `FAILED` \| `STALE` | **视觉资产的生产态**，与 `canon_status`（定稿态）**正交**；下游只等它（`11` §2.6.1） |
| `Envelope` | `{contract_version:int, producer:string, input_state_hash:string}` | **公共外壳，一律「平铺」在契约顶层，不再嵌套**：每个契约 JSON 的顶层必须直接含这三个键（见 §2.2 示例）。与 §2.13 的 `StageEnvelope` 的关系：`StageEnvelope.output` **直接是**本卷的某个契约对象（含平铺的 `Envelope` 三键），**不再额外加壳** |

## 3. 差距（逐条：现状 → 缺口 → 影响）

| # | 现状 | 缺口 | 影响 |
|---|---|---|---|
| 02-1 | 章节计划/评审/提取的 JSON 形状只存在于 Prompt 文字里 | 无 `json_schema`、无显式契约、无版本 | 输出漂移无法检测（旧文档 C2） |
| 02-2 | `StateDiff` 在旧文档中是空壳（`[]` 与 `{}`） | 无字段、无子结构 | 「回写世界状态」无载体（对应 G2） |

| 02-4 | `ReviewVerdict` 无枚举，PASS 靠子串匹配 | 无 `verdict` 枚举、无 `checks_run`、无 `machine_checkable` | 评审不可信（对应 G3） |
