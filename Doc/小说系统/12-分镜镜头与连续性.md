# 12 · 分镜镜头与连续性

> 本卷定义分镜与镜头层：Scene→Sequence→Shot→Beat 的结构、表演/空间/镜头/时间轴各层字段，以及**把「上一镜结束状态 = 下一镜起始状态」变成可机器校验的规则**。旧文档把这条强约束交给 LLM 比对，本集明确改为代码断言。

## 0. 本卷范围与不做什么

**范围**

- 分镜层级结构与每层的职责。
- Scene Breakdown 与 Director Intent 的输入输出要求。
- 表演层、空间层、镜头层、时间轴层的字段与枚举。
- **连续性校验规则**（逐字段比对，本卷核心）。
- 转场类型与节拍覆盖。

**不做**

- 不定义字段的完整契约 → `02` §2.7 / §2.9。
- 不定义生成参数 → `02` §2.8。
- 不定义四类专项 Prompt 写法 → `13`。
- 不定义叙事状态映射 → `11` §2.3。

## 1. 现有落点

### 1.1 叙事分镜存储

- 表 `shots`（`NovelDb.cpp:129`，块 v4）；索引 `idx_shots_scene`（`:149`）。
- 结构体 `NovelVisual::ShotRow`（`NovelVisual.h:48-68`）：

```
id, scene_id, ord, duration_note, camera_id, character_ids_json, action,
expression, prop_ids_json, lighting_id, composition_id, dialogue, narration,
sfx, mood, prompt_text, negative_text, reference_json, canon_status("PROPOSED")
```

**评价**：字段是「叙事描述」而非「可校验结构」——`duration_note` 是自由文本（**没有数值时长**）、`character_ids_json` 无位置/朝向/姿态、无 `start_state`/`end_state`。**连续性无法机器校验的根因在此。**

### 1.2 生成分镜存储

- `video::Shot`（`VideoTypes.h:68-92`）与 `VideoProject`（`VideoProject.h:18-47`），见 `02` §2.8。
- `VideoProject.cpp:33-107 Sanitize`：宽高对齐、帧数对齐、参考图截断——**这是当前唯一的「自动纠正」机制**。

### 1.4 现状缺口

- **`shots` 表没有任何起止状态字段** → 连续性 I7 无数据基础。
- 无 `Sequence` 层级（只有 Scene→Shot）。
- 时间轴精度无保障（`duration_note` 是文本）。
- 无转场类型字段。

## 2. 目标设计

### 2.1 层级结构

```
Chapter
 └── Scene          （scenes，正文链产出，01 §2.5）
      └── Sequence  （新增：同一场内的戏剧单元，1–4 个）
           └── Shot （shots，本卷核心）
                └── Beat （shots.timeline，0.1s 精度）
```

**Sequence 的来源**：`V1 SCENE_BREAKDOWN` 按「目标变化」切分（一个目标达成/失败 = 一个 Sequence 结束）。不增表，用 `shots.ord` 的分段表示（`sequence_index` 进 `reference_json` 或动态字段）。

### 2.2 `SCENE_BREAKDOWN` 七要素（旧文档 `02` 原文保留）

每场必须分析出：

| # | 要素 | 说明 |
|---|---|---|
| 1 | `SceneGoal` | 该场要达成什么 |
| 2 | `CharacterGoal` | **每个在场人物**各自要什么（可冲突） |
| 3 | `Conflict` | 冲突点（无冲突不成场） |
| 4 | `Emotion` | 情绪基调与走向 |
| 5 | `Information` | 观众应该知道什么（对齐 `mysteries` 的节拍） |
| 6 | `Environment` | 环境与氛围 |
| 7 | `ImportantProps` | 重要道具（对齐 `NarrativeShot.start_state.props`） |

**校验**：`Conflict` 为空 → 该场不应存在（回 `SCENE_PLAN`）。

### 2.3 `DIRECTOR_INTENT` 七问（旧文档 `02` 原文保留）

```
1. 观众应该看到什么？
2. 观众应该知道什么？
3. 观众不应该知道什么？        ← 与不变式 I2 的视觉版（11 §2.3.3 VK1）绑定
4. 核心情绪是什么？
5. 情绪如何变化？
6. 高潮在哪里？
7. 节奏如何变化？
```

**产物**：`EmotionalCurve` = `[{shot_id, intensity:0-100, note}]`，按镜序列。

**新增机器校验**：

| # | 断言 |
|---|---|
| E1 | `intensity` 序列**至少有一个局部极大值**（高潮），且该值 ≥ 80 |
| E2 | 相邻镜的 `intensity` 变化 ≤ 40（防突变；转场镜除外） |
| E3 | 首镜 `intensity` ≥ 20（否则开篇无张力） |

### 2.4 表演层 `Performance`（12 项，字段见 `02` §2.7）

`expression` / `eyes` / `breathing` / `posture` / `body_movement` / `hand_movement` / `head_movement` / `weight_shift` / `walking` / `stopping` / `reaction` / `pause`

**规则**：

| # | 规则 |
|---|---|
| PF1 | 12 项**全部必填**（可为 `"none"`），不允许留空——留空是「没设计」，`"none"` 是「明确不动」 |
| PF2 | `pause` 必须是数值（秒，0.1s 精度），且 ≤ `shot.duration` |
| PF3 | 每个 `Beat`（§2.8）只能绑定一个 `Performance` 切片；同一 shot 内不得出现两段语义相同的表演 |
| PF4 | 表演必须与 `character_status.emotion_json` 的基线相容（`11` §2.3.1）；明显背离需在 `DirectorIntent` 中说明理由 |

### 2.5 空间层 `Spatial`（字段见 `02` §2.7）

`character_positions[{entity_id, x_rel, y_rel}]` / `facing` / `distance_m` / `height` / `movement_path` / `occlusion` / `layers{foreground, midground, background}`

**规则**：

| # | 规则 |
|---|---|
| SP1 | `x_rel` / `y_rel` ∈ [0, 1]（相对画面坐标），**保证可机器比较** |
| SP2 | 同一 shot 内两个角色的 `distance_m` 与 `x_rel/y_rel` 差必须一致（距离与画面位置不能矛盾） |
| SP3 | `occlusion` 非空时，被遮挡者必须在 `layers` 中被显式归属 |
| SP4 | **位置变化只能由 `movement_path` 解释**；无 `movement_path` 而位置变化 → `continuity_break` |

### 2.6 镜头层 `Camera`（字段见 `02` §2.7）

- 景别 `shot_size`（7 档）：`extreme_wide` / `wide` / `full` / `medium` / `medium_close` / `close_up` / `extreme_close_up`
- 运动 `movement`（10 种）：`static` / `pan` / `tilt` / `dolly` / `truck` / `push_in` / `pull_out` / `tracking` / `orbit` / `handheld`
- 参数：`position` / `height` / `angle` / `lens_mm` / `composition` / `focus` / `dof` / `framing`

**规则**：

| # | 规则 |
|---|---|
| CM1 | `lens_mm > 0`；`shot_size` 与 `lens_mm` 需相容（如 `extreme_wide` 配 `>85mm` 判 `low`） |
| CM2 | 相邻镜若非同 `shot_size` 且非「正反打」关系，景别跨度 > 4 档时记 `low`（跳跃感） |
| CM3 | `movement != static` 时，`Beat` 的时间轴必须体现运动的起止时间 |
| CM4 | 同一 Sequence 内 `movement` 不得全部相同（防呆板），除非 `DirectorIntent` 声明「固定机位」为该场风格 |

### 2.7 **连续性：机器校验规则**（本卷核心）

> **旧文档把 `Shot N Ending State = Shot N+1 Starting State` 交给 LLM 比对。本集明确：这是纯代码断言（`06` §2.3 K09），不允许 LLM 介入。**

#### 2.7.1 校验对象

`NarrativeShot.start_state` / `end_state`（`02` §2.7 `StateSnapshot`），逐字段比对：

| # | 比对字段 | 允许的变化条件 |
|---|---|---|
| C1 | `characters[].entity_id` 集合 | 只允许**增加**（新角色入镜）或**移除**（离镜），且移除者必须在本镜的 `movement_path` 或 `transition` 中有交代 |
| C2 | `characters[].position` | 必须能由该角色在本镜的 `spatial.movement_path` 解释；无路径而位置变 → **失败** |
| C3 | `characters[].facing` | 变化必须伴随 `movement_path`（转身）或 `performance` 中的 `head_movement`/`body_movement` |
| C4 | `characters[].pose` | 必须由 `performance.posture` + `body_movement` 解释 |
| C5 | `characters[].hands` | 必须由 `performance.hand_movement` 解释 |
| C6 | `characters[].clothing` | **只允许在明确事件后变化**（如换装），且该事件须在 `ChapterPlan.events` 中；否则失败（这是旧文档「禁止服装无原因跳变」的落地） |
| C7 | `characters[].injury` | 只允许**单向加重**或**在明确治疗后减轻**；无因减轻 → 失败 |
| C8 | `props[].holder_id` | 变换必须由 `performance`（交/接）或 `Spatial`（放下/拾起）解释 |
| C9 | `props[].state` | 变化必须有事件；否则失败 |
| C10 | `lighting` | **只允许**在 `time_label` 变化、或本镜内发生光源事件时变化 |
| C11 | `environment` | 只允许在明确事件后变化（如打碎窗户/起火） |
| C12 | `camera_position` | 与下一镜 `camera` 的 `position` 一致（镜头位置也是连续量） |

#### 2.7.2 校验产物

```
ContinuityReport{
  scene_id, shot_count,
  passed: bool,
  breaks: [{
    from_shot: TempId, to_shot: TempId,
    field: "characters[3].clothing",
    before: "灰袍", after: "黑袍",
    explainable: bool,          // 是否有事件可解释
    related_event_id: Id|0,
    severity: high|mid
  }]
}
```

**规则**：

| # | 规则 |
|---|---|
| CT1 | `breaks` 中存在 `severity=high` 且 `explainable=false` → `passed=false`，回 `V9 STORYBOARD` 重做 |
| CT2 | `explainable=true` 的 break **不算失败**（正常剧情变化），但必须记录 `related_event_id` |
| CT3 | 校验是**纯代码**；`checks_run` 必须包含 `invariant.shot_continuity`（`06` §2.3 K09） |
| CT4 | 校验失败**不得**自动修正 `end_state`；必须回到上游（防止「用下一镜去迁就上一镜」的雪崩） |
| CT5 | `duration` 之和与场景时长的偏差 > 10% 记 `mid` |

### 2.8 时间轴与节拍

- `Beat`（`02` §2.9）：`start` / `end` 精度 **0.1s**；`end > start`。
- 校验：① 首 `beat.start == 0`；② 末 `beat.end == shot.duration`；③ beats 互不重叠；④ **覆盖无空隙**（`beat[i].end == beat[i+1].start`）。
- 每个 Beat 可绑定：`performance` / `camera` / `dialogue` / `sfx` / `bgm`。

### 2.9 转场

`transition`（`02` §2.7 枚举 6 种）：`cut` / `match_cut` / `dissolve` / `fade` / `whip_pan` / `camera_motion`

**规则**：

| # | 规则 |
|---|---|
| TR1 | 同 Sequence 内默认 `cut`；换 Sequence 用 `dissolve`/`fade`；`match_cut` 必须有明确的匹配元素（形状/动作/声音），且该元素在 `ContinuityReport` 中被记录 |
| TR2 | `transition != cut` 时，`camera_position` 的连续性检查（C12）**放宽**，但必须给出理由 |
| TR3 | 同一场次连续 3 镜都用 `fade` → 记 `low`（节奏拖沓） |
