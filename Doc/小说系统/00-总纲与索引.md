## 2. 目标设计

### 2.1 系统全景：一条主轴 + 两条链

系统唯一的目的是：**把原本要塞进 Prompt 的长期信息，全部变成可检索、可更新、可验证的外部状态**。Agent 只负责当前阶段的推理与生成；状态库与 MCP 负责「拿数据、写数据、查数据」。

因此本系统是「一条主轴 + 两条链」：

- **主轴（世界状态）**：`novel.db`。所有长期事实的唯一权威。
- **正文链**（核心）：世界状态 → 章节计划 → 事件 → 场景 → 正文 → 评审 → 状态差异 → 提交 → 状态更新 → 下一章。**必须闭环**。
- **影视化链**（消费）：正文链产出的 `Scene` 是其唯一输入；叙事状态 → 视觉状态 → 分镜 → 镜头 → 专项 Prompt → 生成。**可独立重跑，不回写正文**。

```mermaid
flowchart LR
  W[("世界状态 novel.db")] --> T["正文链 01-10"]
  T -->|Scene / 叙事状态| V["影视化链 11-13"]
  T -->|StateDiff + Commit| W
  V -->|视觉 Canon / 生成结果| W
```

### 2.2 阅读顺序

1. 先读本卷（`00`）建立全景与术语。
2. 正文链按 `01 → 02 → 03 → 04 → 05 → 06 → 07 → 08 → 09 → 10` 顺序。
3. 影视化链按 `11 → 12 → 13` 顺序，在正文链之后读。
4. 任意阶段需要契约或字段定义时，回 `01` / `02`，不要在中间卷里找。

### 2.5 术语统一表

旧文档在 `00_MASTER_WORKFLOW`、`09_STATE_AND_MCP`、`11_DATA_CONTRACTS` 三处各列了一遍实体，且不完全一致。本集收敛为下表，**此后只使用「规范名」**：

| 地点 Location | `entities(kind='location')` + `location_details` | 层级用 `location_details.parent_id` |
| 物品 Item | `entities(kind IN ('item','prop','treasure','clothing'))` + `item_details` | 旧文档的 Item / ItemState / ItemHistory 拆为：定义＝`item_details`，位置与状态＝字段系统，流转＝`entity_ownerships` |
