# 09 · 无人值守运行规范

> 本卷回答「怎么连跑几百章不停不崩」：运行模式、**量化的停止条件**、重试与限流、模型分层与成本控制、检查点与人工复核、异常与中断恢复、可观测性。旧文档只写「连续失败就停」，本卷把每个阈值变成具体数字。

## 0. 本卷范围与不做什么

**范围**

- 三种运行模式及其适用与切换规则。
- 停止条件：可自动推进 vs 必须停下，**全部量化**。
- 重试、退避、限流的参数。
- 模型分层（哪个阶段用哪个模型）与单章成本预算。
- 检查点周期与人工复核清单。
- 异常、中断、崩溃的恢复路径。
- 可观测性：必须产出什么日志与报告。

**不做**

- 不定义阶段顺序 → `03`。
- 不定义校验项 → `06`。
- 不定义提交事务 → `07`。
- 不定义字段门禁 → `08`。

## 1. 现有落点

### 1.1 运行方式现状

- 无「运行模式」概念；生成由 UI 按钮单次触发（`NovelView.cpp:249-295`）。
- 单次生成跑在 worker：`async::RunOnWorker`（`NovelView.cpp:257`）→ 独立 `db::sqlite::Database` 连接（`:258-260`）→ `NovelDirector::GenerateChapter`（`:264-266`）；进度经 `PostToUi` 流式（`:267-278`）。
- 取消：`g_cancelGen`（`:48` 声明、`:298-301` 置位、`:268` 检查、`:263` 透传）。
- 无批处理、无队列、无断点续跑。

## 2. 目标设计

### 2.1 运行模式

| 模式 | 行为 | 提交策略（`07` §2.5） | 适用 |
|---|---|---|---|
| `manual` | 每完成一章停下，等 UI 确认 | `PROPOSED` | 有人在看；调试 |
| `semi` | 连续跑到检查点（默认 10 章）停下 | `PROPOSED`，检查点统一确认 | 常规使用 |
| `auto` | 连续跑到目标章数或命中停止条件 | `CANON`（**必须满足 `07` §2.3 G1–G5**） | 无人值守 |

**模式是工程级配置**，每次运行写入 `audit_logs`（`action='run_mode'`）。

**切换规则**：

- `auto` 的前置条件（全部满足才允许启动）：① `07` §2.3 的 G1–G5 在最近一章已验证通过；② `06` §2.3 的 K01–K29 校验器**全部可用**（不允许有「待实现」的项）；③ LLM 与 Comfy 连通性自检通过。
- 运行中从 `auto` 降级到 `semi` 的触发：见 §2.2 的停止条件。

### 2.2 停止条件（**全部量化**）

#### 必须停下（`STOP`）

| # | 条件 | 阈值 | 停下后输出 |
|---|---|---|---|
| S1 | 机器校验连续失败 | `>= 2` 次（同一章同一 check_id） | 冲突清单 + 相关 `ValidationReport` |
| S2 | 评审 `FAIL` 累计 | `>= 3` 次（同一章） | 完整 `ReviewVerdict` + `RepairReceipt.unresolved` |
| S3 | **仅语义判断且 FAIL** 的连续章数 | `>= 2` 章（`06` §2.7 M2） | 需人工看的段落 |
| S4 | 契约校验失败（同阶段，含 1 次重试后） | `>= 2` 次 | 原始模型输出 + 违反的契约项 |
| S5 | 单章成本超预算 | `> 2 ×` 单章预算（§2.4） | 成本明细 |
| S6 | LLM/网络不可用 | 连续失败 `>= 5` 次且退避后仍失败 | 最后一次错误 |
| S7 | Comfy 不可用且本章需要出图 | 探活失败 `>= 3` 次（间隔 5s） | `HealthSummary()` |
| S8 | 状态自相矛盾且回退不可用 | 命中 `07` §2.6 但无法自动处置 | 冲突清单 |
| S9 | 引用不存在的实体超过阈值 | 单章 `>= 10` 处（`code=contract`） | 缺失清单（通常意味着初始化未完成，指向 `10`） |
| S10 | `field_defs` 条数超上限 | `> 500`（`08` §2.3） | 新增失败清单 |
| S11 | 磁盘/快照写入失败 | 任一 | 阻断提交（不变式 I11） |
| S12 | 需要无法推断的用户决策 | 命中 | 「需要什么决策、在哪一步」 |

#### 可自动推进（`CONTINUE`）

| 情形 | 处理 |
|---|---|
| 契约失败第 1 次 | 带错误反馈重试 1 次 |
| 网络 5xx / 429 | 指数退避重试（§2.3） |
| 校验失败第 1 次 | 回上游阶段重做 |
| 评审 FAIL 第 1–2 次 | `CHAPTER_REPAIR` |
| 工具重复调用 `>= 3` | 中止工具环，该阶段退化为无工具 |
| 生成单镜失败 | 标记该镜 `FAILED`，继续其余镜 |
| 生成任务被中断 | `phase=Idle`，**不算失败**，可重试 |
| `low` 级 issue | 记录，不阻断 |
| 伏笔超期告警（未到阻断档） | 记录进复核清单 |

### 2.3 重试、退避与限流

| 项 | 参数 |
|---|---|
| 网络重试 | 最多 **4** 次；退避 `2s → 4s → 8s → 16s`，±20% 抖动 |
| 429（限流） | 尊重 `Retry-After`；无该头则退避从 **10s** 起 |
| 契约重试 | **1** 次（`03` §2.6） |
| 校验重试 | **2** 次 |
| 修复轮次 | **3** 次 |
| LLM 并发 | **1**（串行）。理由：现有 `async::RunOnWorker` 为 4 线程池，但小说生成有强顺序依赖；并发留给未来的「多章并行规划」，需先解决状态冲突 |
| Comfy 并发 | 沿用现有单任务串行（`VideoTaskRunner` 单例） |
| 每章最大 LLM 调用数 | **40**（超出即 `S5`）。按 `03` §2.2 的阶段数 + 重试上限估算 |
| 请求间隔（同 Provider） | ≥ 200 ms（防限流） |

### 2.4 模型分层与成本控制

| 阶段 | 模型档位 | 配置项 | 理由 |
|---|---|---|---|
| `CHAPTER_INIT` / `CONTEXT_ASSEMBLY` | **不调用 LLM** | — | 纯检索与裁剪 |
| `CHAPTER_GOAL` / `OUTLINE` | 中 | `openaiModelPlanner` | 结构规划，中档够用 |
| `EVENT_PLAN` / `SCENE_PLAN` / `CHARACTER_PLAN` / `ITEM_PLAN` / `FORESHADOW_PLAN` | 中 | `openaiModelPlanner` | 同上 |
| **`NOVEL_WRITE`** | **高** | `openaiModelWriter` | 正文质量是唯一不可将就处 |
| **`CHAPTER_REVIEW`** | **高且与 Writer 不同** | `openaiModelCritic` | `06` §2.7 M5：不同模型才可能有效复核 |
| `CHAPTER_REPAIR` | 高 | `openaiModelWriter` | 与正文同档 |
| `STATE_EXTRACT` | **低** | `openaiModelDefault` | 结构化抽取，低档够用；且受 `07` §2.2 的 D1–D8 代码校验兜底 |
| T2–T9 合并执行时 | 中 | `openaiModelPlanner` | 减少调用次数 |
| 视觉链 V1–V8 | 中 | 新增 `openaiModelVisual` | — |
| `PROMPT_GEN`（V10） | **低** | 新增 `openaiModelPrompt` | 有 `PromptArtifact` 契约约束 |
| `GENERATION`（V11，可选下游） | **不调用 LLM** | — | 仅提交 Comfy 出图；影视化链终点是 V10 |

**单章成本预算**（`max_cost_per_chapter`）：

| 项 | 预算 |
|---|---|
| LLM 调用次数 | ≤ 40（硬上限，超出即 `S5`） |
| 「高」档调用次数 | ≤ 8 |
| 出图次数 | ≤ 2 镜/章（超出的进下一轮） |
| 单章墙钟时间 | 默认 ≤ 30 分钟（可配）；超时告警，不阻断 |
| 全书预算 | 启动时给出「预计调用数 × 单价」估算，超出配置上限则拒绝启动 `auto` |

**成本可见性**：每章产出 `cost_report.json`（各阶段调用次数、档位、token 数、耗时）。**没有这个，几百章的账算不清。**

### 2.5 检查点与人工复核

| 项 | 周期 | 产物 |
|---|---|---|
| 检查点 | 每 **10** 章（可配） | `checkpoint_ch<A>_<B>.md`：该区间所有 `high` issue、被自动升 CANON 的字段定义（`08` §2.3）、`semantic_only` 章清单、成本合计 |
| 伏笔对账 | 每 **10** 章 | 未回收伏笔按超期程度排序（`06` §2.3 K10） |
| 抽样复核 | 每 **10** 章抽 **2** 章 | 由不同模型重评，差异进 `audit_logs`（`06` §2.7 M3） |
| 依赖传播复查 | 每次「改设定」或 CANON 回退后 | 沿 `dependencies` 产出的待复查章节清单 |
| 全书面板 | 随时 | 章数、字数、成本、未结线索数、超期伏笔数 |

### 2.6 异常与中断恢复

| 情形 | 恢复 |
|---|---|
| 进程崩溃 | 读 `work/ch<NNN>/_manifest.json` → 找最后一个「产物完整且 `input_state_hash` 一致」的阶段 → 从下一阶段续跑（`03` §2.7 P5） |
| 断电/重开机 | 同上；因提交有事务（`07` §2.3），不会留半成品 |
| LLM 中断 | 该阶段视为未完成，产物不落盘，重跑 |
| Comfy 中断 | `Cancelled → Idle`（现有语义），该镜重试 |
| Comfy 重启 | `ComfySession` 自动重连续跑 `PollHealth`（`ComfySession.cpp:539-581`）；`promptId` 失效 → 该镜重提交 |
| 出图任务遗留在 `RUNNING`（崩溃/断电） | 启动时 `novelcore::ReapStaleImageJobs(db, 0)` 把 `RUNNING`/`QUEUED` 改判 `FAILED` 并写 `audit_logs(actor='startup_reaper')`（`11` §2.6.5，**已实现**）；**headless / MCP 入口必须一并调用** |
| 状态被旁路篡改 | 状态哈希变化 → 全部下游失效（`04` §2.5 H3/H5），从最早失效阶段重跑 |
| 目标章数达成 | 正常结束，产出全书报告 |
| 用户中途取消 | 保存已完成章 + 当前章中间产物；下次从断点续跑 |

**恢复的硬要求**：任何恢复路径**不得**从头重跑全书。

### 2.7 可观测性

**必须产出**（缺一即视为本次运行不可诊断）：

| 产物 | 内容 | 位置 |
|---|---|---|
| 运行日志 | 每阶段一条（阶段/尝试数/耗时/成本/结果状态） | `log::` + 可选 `SHINE_LOG_FILE` |
| `work/ch<NNN>/_manifest.json` | 阶段 → 产物文件 + `input_state_hash` + 时间戳 | 工程目录 |
| `cost_report.json` | §2.4 的字段 | 章目录 |
| `checkpoint_ch<A>_<B>.md` | §2.5 的内容 | 工程目录 |
| `audit_logs` 汇总行 | `actor='orchestrator'`, `action='commit_chapter'`, `detail` 含 `diff_hash` | 数据库 |
| 停下时的 `stop_report.md` | 停止条件编号（S1–S12）、现场、需要的决策、建议动作 | 工程目录 |

**日志纪律**（沿用本仓规则）：中文文案只走 `ComfySession::HealthSummary()/BusyDetail()/LastErrorDetail()` 这类既有入口，不得把「执行中」写成「卡死/断开」。

## 3. 差距（逐条：现状 → 缺口 → 影响）

| # | 现状 | 缺口 | 影响 | 严重度 |
|---|---|---|---|---|
| 09-1 | 无运行模式 | 只有单章手动触发 | 「说到第 N 章就跑到底」不成立（G15 关联） | **S** |
| 09-2 | 无成本控制，无调用计数 | 无预算、无上限 | 跑几百章的账不可控 | **S** |
| 09-3 | `auto` 与 Canon 需人工确认冲突 | 见 `07` §2.5 | 连写不成立 | **S** |
| 09-4 | 无检查点 | 跑 100 章后无从复核 | 静默劣化不可发现 | **S** |
| 09-5 | 无成本报告 / 无运行报告 | 无法诊断 | 出问题只能从头查 | **A** |
| 09-6 | 无重试/退避参数 | 网络抖动即失败 | 长跑必中断 | **A** |
| 09-7 | 模型分层未落地（`openaiModelPlanner/Writer/Critic` 存在但无按阶段路由） | 全部走 `openaiModelDefault` | 成本高且质量失衡 | **A** |
| 09-8 | 评审与写作可同模型 | 无交叉复核 | 自评全 PASS（`06` §3 06-5） | **A** |
| 09-9 | 无停止条件实现 | 失败即整章返回错误 | 会整体停或死循环 | **S** |
| 09-10 | `log::` 未 `Init()` 时静默 | 无人值守下可能无日志 | 现场丢失 | **A** |
| 09-11 | 无并发/限流策略 | 可能触发 Provider 限流 | 长跑不稳 | **B** |
| 09-12 | 无全书预算估算 | `auto` 可被无意启动 | 成本失控 | **B** |

## 4. 验收判据

- [ ] §2.1 三种模式的提交策略明确，且 `auto` 的前置三条件可判定。
- [ ] §2.2 的停止条件 S1–S12 **每条都有具体数字阈值**；全集中不存在「连续失败」「过多」这类无数值表述。
- [ ] §2.2 的 `CONTINUE` 表覆盖全部可自动恢复情形，且与 `03` §2.6 一致。
- [ ] §2.3 的重试与退避参数全部具体（4 次、2/4/8/16s、429 从 10s 起）。
- [ ] §2.4 的模型分层覆盖 `03` §2.2 的**每一个**阶段（含视觉链），且 `openaiModelCritic ≠ openaiModelWriter` 是硬要求。
- [ ] §2.4 的单章预算（40 次调用 / 8 次高档 / 2 镜）是具体数字。
- [ ] §2.5 的检查点周期（10 章）与抽样复核（2 章）明确。
- [ ] §2.6 明确「任何恢复路径不得从头重跑全书」。
- [ ] §2.7 的六类产物齐备，且 `stop_report.md` 必须带停止条件编号。
- [ ] §3 的 12 条差距在 `00` §3 有编号对应。
