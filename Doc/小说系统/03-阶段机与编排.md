# 03 · 阶段机与编排

> 本卷定义「谁在什么条件下跑下一步」：两条链各自的阶段枚举与顺序、每阶段的进入/退出条件、失败与重试、断点续跑与幂等、中间产物落盘位置、以及量化停止条件。契约见 `02`，判据见 `06`。

## 0. 本卷范围与不做什么

**范围**

- 三分职责：总控 / 专项 Agent / 状态层。
- **拆链**：正文链与影视化链各自的阶段表（旧文档把两者捆成 35 步线性流水，本卷拆开）。
- 每阶段的输入、产物、进入条件、退出条件、失败处理。
- 按需加载规则、总控循环、重试与幂等、断点续跑与落盘。
- 量化停止条件（区分「可自动推进」与「必须停下」）。

**不做**

- 不定义契约字段 → `02`。
- 不定义上下文如何裁剪 → `04`。
- 不写 Prompt 文本 → `05`。
- 不定义校验器细则与阈值 → `06`。

## 1. 现有落点

### 1.1 正文链现状（`src/agent/NovelDirector.cpp`）

- `Phase` 枚举（`NovelDirector.h:18-30`）：`Idle, Analyze, Plan, Retrieve, Write, Review, Revision, Extract, Save, Done, Failed`。
- 阶段序列（`GenerateChapter`，`:157-304`）：Analyze(173) → Retrieve(180) → Plan(192) → Write(210) → Review/Revision 循环(240-263) → Extract(269) → Save(285) → Done(300)。
- 请求/结果（`NovelDirector.h:34-55`）：`GenerateChapterRequest{chapter_id, user_hint, max_revisions=3}`、`GenerateChapterResult{chapter_id, title, body, plan_json, critic_json, revisions, callLog}`、`GenerateChapterProgress{phase, text_delta, percent, note}`。
- 进度经 `on_progress` 回调 → `PostToUi` 流式（`NovelView.cpp:267-278`）。
- **失败即整体 `unexpected` 返回**，无中间产物落盘；重跑从 Analyze 重来。

### 1.2 影视化链现状（`src/video/`）

- `VideoTaskPhase`（`VideoTaskRunner.h:32-43`）：`Idle, Resolving, Uploading, Compiling, Submitting, Running, ReadingHistory, SavingMedia, Done, Failed`。
- 状态机由 `VideoTaskRunner::Instance()` 单例承载：`Start`（`VideoTaskRunner.cpp:129-265`）→ worker 内 Resolving/Uploading/Compiling → 回 UI 线程 `ValidateApiGraph`(226) → `SubmitPromptJson`(246) → `PollQueue`(365-414) → Done/Failed。
- 超时常量（`VideoTaskRunner.cpp:40-43`）：`kQueueGraceMs=8000`、`kSilenceMs=20000`、`kHistoryTimeoutMs=60000`、`kTotalTimeoutMs=2h`。
- **中断 ≠ 失败**：`TaskState::Cancelled` → `phase=Idle`（`:404-412`）。
- `Tick()`（`:546-558`）由 UI 每帧驱动。

### 1.3 工具环现状（`src/agent/`）

- `ToolRegistry::RunToolLoop`（`ToolRegistry.cpp:131-268`）：`kMaxToolCalls=20`（`ToolRegistry.h:46`）、`kMaxRepeat=3`（`:47`）；`CheckLoopGuard`（`:112-127`）拦截超限与连续重复。
- `AgentKit::Run`（`AgentKit.cpp:1057`）封装工具环，但**全仓唯一调用点是 `AgentKit.cpp:1507`（自检）**——生产路径未接入。
- `AgentKit::RegisterToolsFor`（`:831-875`）按 `agentId` **C++ 硬编码分支**决定工具集合。

### 1.4 编排相关事实

- 无总控进程：UI 按钮直接调 `NovelDirector::GenerateChapter`（`NovelView.cpp:249-295`）。
- 无阶段级产物落盘，无 checkpoint，无幂等键。
- 默认 `max_revisions=2`（UI 传值，`NovelView.cpp:265-266`），而契约默认是 3。

## 2. 目标设计

### 2.1 三分职责

| 角色 | 负责 | **不负责** |
|---|---|---|
| **总控 Orchestrator** | 读 Workflow State → 判定当前阶段 → 取最小上下文 → 调专项 → 校验产物 → 落盘 → 判定下一阶段 | 不持有任何专项 Prompt；不生成正文；不改世界状态 |
| **专项 Agent** | 当前阶段的推理与生成（规划/写作/评审/提取/导演/分镜/提示） | 不决定下一步是什么；不写库（只产出契约对象） |
| **状态层（MCP / 本地工具）** | 拿数据、写数据、查数据；校验；落盘；审计 | 不做推理 |

**这是本系统与「一个大 Prompt」的根本区别**：总控只知道「有哪些能力可以调用」，不知道也不缓存这些能力的具体 Prompt。

**影视化链的终点是 `V10 PROMPT_GEN`**（产出可用的分镜提示词）。阶段表到此结束。

`V0 ASSET_PIPELINE` 是**前置**阶段：角色/场景资产的生产流水线（**正脸 → 四视图 → 基础身体 → 服装**），承载表 `visual_artifacts`；**生产状态机与派生链见 `11` §2.6，依赖等待与降级见 `11` §2.7**。它必须先于 `V9 STORYBOARD` 完成（否则分镜无参考图）。

`V11 GENERATION`（提交 Comfy 出图）是**可选下游动作，不属于本链的阶段表**：无评审、无重生成循环，只有 `09` §2.2 的「单镜失败不阻断其余镜」隔离。**分镜图不做生成评审**（`02` §2.6 的 `target_type` 已移除 `generation`）。

**明确边界（旧文档的 `08` 已述，本集强化）**：影视化链**不修改正文**，**不提升为 `CANON`**（视觉 Canon 独立走 `visual_canon_logs`）。

### 2.3 每阶段的进入 / 退出条件

| 阶段 | 进入条件 | 退出条件（全部满足才前进） |
|---|---|---|
| `CHAPTER_INIT` | 存在 `chapters` 行且 `volume_id` 有效 | 取到前章摘要 + 开放线索；状态哈希已计算 |
| `OUTLINE` / `EVENT_PLAN` / `SCENE_PLAN` | 上游产物通过 `02` §2.0 C3–C5 校验 | 契约校验通过 |
| `CONTEXT_ASSEMBLY` | `ChapterPlan` 已就绪 | `ContextPack` 未超预算（`04` §2.4） |
| `NOVEL_WRITE` | `ContextPack` + `ChapterPlan` 齐备 | 正文非空且长度落在 `word_target ±30%` |
| `CHAPTER_REVIEW` | 正文已落盘 | `verdict` 为枚举值（**非子串判定**）；`checks_run` 非空 |
| `CHAPTER_REPAIR` | `verdict=FAIL` 且存在 `severity=high` 的 issue | `RepairReceipt.unresolved` 为空，或达到 `max_revisions` |
| `STATE_EXTRACT` | 正文与评审结论已定 | `StateDiff` 契约校验通过；`no_change_declared` 与子数组一致 |
| `STATE_VALIDATE` | `StateDiff` 就绪 | `06` §2.3 全部机器校验项通过 |
| `COMMIT` | 评审 PASS **且** 校验 PASS | 快照已写；各表事务提交成功 |
| `ASSET_PIPELINE`（V0） | 该章 `scene_cast` 涉及的实体都有 `visual_assets` 记录 | 全部资产 `status ∈ {SHEET_READY, WARDROBE_READY, READY}`，**或**已按 `11` §2.7 显式降级并记账（K28/K29） |
| `CONTINUITY` | 同一场景全部 `NarrativeShot` 就绪 | I7 全链通过（`12` §2.7） |

### 2.4 按需加载规则

**禁止**：启动时加载全部 Agent 的 system prompt。

**必须**：

1. 总控维护一张「阶段 → 能力名」表（能力名 = `AgentDefRow.agent_id`）。
2. 进入阶段 N 时，只加载该阶段对应 Agent 的 `system_prompt`（`AgentKit::GetAgentDef`）与该阶段允许的工具白名单（`AgentKit::ResolveTools`）。
3. 离开阶段即释放；不得跨阶段复用 Prompt 文本。
4. 工具白名单必须来自 DB（`agent_defs.tools_json`）与阶段声明的交集，**不得沿用 C++ 硬编码分支**（见 §3）。

### 2.5 总控循环

```
read WorkflowState（当前链 / 当前章 / 当前阶段 / 已完成的阶段 / 错误）
  ↓
determine CurrentStage
  ↓
determine RequiredCapability（阶段 → agent_id + 工具白名单）
  ↓
retrieve MinimalContext（04）
  ↓
call Specialist（产出契约对象）
  ↓
validate（02 契约校验 + 06 机器校验）
  ↓
save（阶段产物落盘 §2.7）
  ↓
determine NextStage
  ↓
continue / stop（§2.6）
```

**循环不变式**：每次 `continue` 前必须已落盘当前阶段产物，且 `WorkflowState` 可被外部读取（崩溃后能从这里恢复）。

### 2.6 失败、重试与停止条件（量化）

| 情形 | 处理 | 依据 |
|---|---|---|
| 契约校验失败（模型输出不合规） | 重试 **1 次**（带错误反馈重问）；仍失败 → `fail` | `code=contract` |
| 网络/限流（`retryable=true`） | 指数退避重试，上限 `09` §2.3 | `code=network` / `http_429` |
| 机器校验失败（不变式被破坏） | 回到 `STATE_EXTRACT` 重提；连续 2 次失败 → **停下** | `06` §2.3 |
| 评审 `FAIL` | 进入 `CHAPTER_REPAIR`；累计超过 `max_revisions` → **停下** | `03` §2.3 |
| 同一工具连续重复 ≥3 次 | 中止工具环 | `ToolRegistry` `kMaxRepeat` |
| 工具调用总数 > 20 | 中止并报错 | `kMaxToolCalls` |
| 生成任务超时 | 单镜 2h 上限（沿用现有），超时 → 该镜 `FAILED`，**不阻断其余镜** | `VideoTaskRunner.cpp:40-43` |
| **缺少无法推断的关键用户决策** | 停下并列出「需要什么决策、在哪一步」 | 旧文档停止条件 1 |
| **需要外部授权**（密钥缺失、付费接口） | 停下 | 旧文档停止条件 2 |
| **不可自动解决的冲突**（状态自相矛盾且无法回退） | 停下并输出冲突清单 | 旧文档停止条件 3 |

**量化阈值**（旧文档只写「连续失败」，本集必须可判定）：

- `max_contract_retry = 1`
- `max_validate_retry = 2`（**S12 已落地**：`GenerateChapterRequest::max_validate_retries`，由 `09` 的 `RunLimits::validation_retries` 下发；`NovelDirector` 用它给「机器校验失败 → 回 `STATE_EXTRACT` 重做」封顶）
- `max_revisions = 3`（**统一取此值**，UI 不得传 2）
- `max_semantic_fail_streak = 2`（连续两章「仅语义判断且 FAIL」→ 停下等人看）
- `max_cost_per_chapter` → `09` §2.4

### 2.7 断点续跑、幂等与中间产物落盘

**落盘约定**（本集新增，直接支撑 G6）：

```
<novelRoot>/<书名>/
  novel.db
  work/                       # 中间产物（非权威，可删）
    ch017/
      01_chapter_goal.json
      02_outline.json
      03_event_plan.json
      04_context_pack.json
      05_scene_plan.json
      06_character_plan.json
      07_item_plan.json
      08_foreshadow_plan.json
      09_chapter_plan.json
      10_review.json
      11_repair_receipt.json
      12_state_diff.json
      13_validation.json
      _manifest.json          # 阶段 → 产物文件 + input_state_hash + 时间戳
  snapshots/                  # 章级快照（07 §2.4）
    ch017.json
```

**幂等规则**：

| 规则 | 内容 |
|---|---|
| P1 | 每个阶段产物文件包含 `input_state_hash`；若当前状态哈希与文件一致，**允许跳过该阶段**（续跑） |
| P2 | 若不一致，该阶段及其**下游全部失效**，从该阶段重跑 |
| P3 | `COMMIT` 是**唯一有副作用的阶段**；必须可重入：重复提交同一 `StateDiff` 不产生重复行（用 `(entity_id, chapter_id, layer)` 唯一键与「先删同键再插」语义） |
| P4 | `NOVEL_WRITE` 落盘前不写 `chapters.body`；避免半成品进权威库 |
| P5 | 崩溃恢复：读 `_manifest.json` → 找最后一个「产物完整且哈希一致」的阶段 → 从下一个阶段继续。**实现进度（S14）**：`_manifest.json` 的 `stage_artifacts`（阶段 → 产物路径 + 字节数 + FNV 内容指纹，由 `NovelRunLoop::ScanChapterStages` 扫工程目录得到）已就位 —— 这是 P5 需要的**输入**；但「从下一个阶段继续」还**没有**做（`Phase` 枚举仍只有 11 个粗阶段，当前续跑粒度 = 章）|

### 2.8 两条链的衔接

- **唯一衔接点**：`scenes`（`01` §2.5）。正文链的 `SCENE_PLAN` 产出 `ScenePlan`，落 `scenes`；影视化链的 `SCENE_BREAKDOWN` 只读 `scenes`。
- **不互相阻塞**：正文链跑到第 N 章后，影视化链可独立对第 1..N 章重跑任意次。
- **共享状态的方式**：影视化链读取的是**已提交（`CANON`）的** `scenes` 与叙事分镜；正文链的 `PROPOSED` 变更不影响已生成的视觉产物，但会让相关 `PromptArtifact` 的 `input_state_hash` 失效（`04` §2.5）。
