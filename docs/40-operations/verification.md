# 验证与证据

## 验证层级

| 层级 | 证明内容 | 不能证明 |
|---|---|---|
| 静态阅读 | 路径、接口、依赖和设计意图 | 运行时可用性 |
| 门禁脚本 | 分层、颜色、主题、编码规则 | 外部服务联调 |
| 离线自检 | 纯函数、状态机、序列化、错误路径 | Qt 视觉和真实网络 |
| 编译 | 当前目标可生成 | 逻辑正确/外部服务可用 |
| 实际运行 | 启动、交互、退出和可见状态 | 未覆盖的路径 |
| 外部联调 | ComfyUI/LLM/MCP 的真实协议 | 本机之外环境 |

## 最小证据格式

```text
[目标] <改了哪个行为>
[命令] <完整命令 + cwd>
[环境] <编译器/Qt/服务/是否 mock>
[结果] <退出码 + 关键输出>
[观察] <实际看到的状态/文件/截图>
[限制] <未覆盖的外部前提或未执行项>
```

不要只写“测试通过”。如果没有运行，写“未运行”，不要把静态检查当运行证据。

## 文档变更验证

1. 枚举新文档和索引链接；
2. 检查每个相对链接的目标存在；
3. 搜索已删除文档目录和旧规则文件；
4. 检查 YAML 元数据中的 `source_of_truth` 路径存在；
5. 检查 `tools/`、`scripts/`、`src/` 没有指向已删除文档的功能性引用。

## C++/UI 验证

- 先运行受影响模块的离线自检；
- 编译 `ShineTVStudio`；
- 启动真实程序，走对应页面/CLI；
- UI 变更用截图或直接观察确认标题、布局、状态和退出；
- 外部服务依赖明确标记，不把离线 mock 当真实联调。

## QML 端到端出图：不能跨进程逐像素比对

`SHINE_QML_REVIEW` + `SHINE_QML_PAGES` 跑出来的 PNG **不是可复现的**：同一份代码、同一台机器、不同进程之间，图片会有大面积差异。2026-09-29 实测（`深空` 主题，1440×900，共 129.6 万像素）：

| 比对 | 差异像素 | 说明 |
|---|---|---|
| 同一二进制连拍两次 | 0 ~ 2243 | 仍非零 |
| 两次**零代码改动**的构建之间，`parity` 对照页 | 38503（2.8%） | 该页源码一个字没改 |
| 用到 `Flex` 的三页（gallery / assets / storyboard），跨构建 | 约 10 万 ~ 12 万（8%） | 与改动无关 |
| `parity` 的 PNG 体积，跨构建 | 46951 B → 77613 B | 同一份代码 |

成因是离屏软件场景图下的抗锯齿/字体落定时序随进程而变，不是内容变化 —— 两张肉眼无法区分的图，逐像素能差出 8%，PNG 体积能差 80%。

**因此：**

- 出图比对的**噪声底**是每张图 2000 px（跨进程）/ 40000 px（跨构建）。小于这个数的差异不必当回事，大于它的差异**也不能**直接判定为回归。
- 判定「内容有没有丢」必须用**同一次运行内**的对照，或挑无文字的纯色区域算精确相同率；
- 判定「布局对不对」用**目视 + 结构推理**（元素个数、是否重叠、是否居中、行高是否取该行最高），不要用像素差；
- **PNG 字节数不是内容指标**（同一条铁律的第二个证据）。

## 验收的退出码必须跟着判据走

**恒 0 的退出码等于没验收。** 2026-09-29 全量排查发现：八份评审取证
（`P03`–`P10` 的 `*Review.cpp`）里有六份是「写完 manifest 就 `std::_Exit(0)`」——
缺图、超时、空图全报成功。后果有两层：按退出码判的 harness 直接吃假绿；
按 `overall: (\w+)` 解析的 harness 读出来是「没有这行」，看起来像**没跑**而不是**跑挂了**。

现在统一走 `src/ui/verify/review/ReviewProbe.h` 的 `FinishOptions` /
`EvaluateShots` / `WriteAndExit`，判据三条：

1. `expected` 里每个文件都存在 → 否则 `MISSING`；
2. 字节数 ≥ `min_bytes`（默认 100B）→ 否则 `UNDERSIZED`（**与缺分开报**：
   一张 40 字节的 PNG 读成 MISSING 会把排障方向指到「抓图没跑」）；
3. 可选 `fail_on_duplicate`：两张图**逐字节相同**即 FAIL。两个图名共用一份
   像素 = 有一张没拍到它该拍的状态。

`WriteAndExit` 写 `overall=PASS|FAIL` 并 `_Exit(ok ? 0 : 1)`。
`P02/P03` 的 Checks 侧同样改成由判据决定退出码。

**每次跑完先对 md5**（见上一节）。字节数不同不算信号，逐字节相同的 md5 才是。

### 跑法

| 场景 | 命令 | 报告 |
|---|---|---|
| P05 八个场景 | `powershell -File scripts/run_p05.ps1 [-Scenes S7,S8]` | `build/p05/p05_S*.txt` |
| 全部视觉评审 | `powershell -File scripts/run_reviews.ps1 [P05 P09]` | `build/reviews/<Pxx>/shots-manifest.txt` |
| QML 页主题矩阵 | `SHINE_QML_REVIEW=<dir> SHINE_QML_PAGES=<页名,...>` | `<dir>/shots-manifest.txt` |

`run_reviews.ps1` 额外核对「`overall` 与退出码是否一致」—— 判 PASS 却退非零
（或反之）本身就是一处假绿，会被单列出来。

⚠️ **取退出码踩了三个坑**（PowerShell 5.1 on Windows）：

1. `Start-Process -PassThru` 返回的 Process 对象**恒不填 `ExitCode`**（直接跑 exe、
   包一层 `cmd /c` 都一样空）——所以 Exit 列长期是装饰品；
2. 只有**前台**执行 `cmd /c`，`$LASTEXITCODE` 才有值；
3. 前台执行没有超时 → 超时用**看门狗进程**实现，**不要**把主体塞进 `Start-Job`
   （实测会丢掉输出，拿不到退出码）。

## 失败处理

- 复现后再改；
- 修复后重跑同一场景；
- 如果用户已有工作区变更导致失败，保留事实并区分基线问题与本次问题；
- 不能通过删除错误日志、吞异常或关闭校验来制造“通过”。
